# 允许零技能推荐：增量规格

Status: implemented。最终规格已通过 PR #37 合入产品 main，合并提交为 `40f4f33667377a31fd4c63593ae2619d8c1cc4af`。[决策理由](decision.md)与本文互相补充；本文完整定义本次变更的行为。产品工作区为隔离工作区（位置未公开），目标分支为产品仓库 `main`，不涉及 DSH 核心修改。

## 目标与范围

修复 skill-selection 在所有候选均不适用时仍发布默认前五项的行为。推荐数量为零到 `skillLimit`，保留有相关技能时的推荐、原生显式加载、完整目录恢复和既有失败处理。仅处理技能推荐；文件排序、其他 Jev 功能及检索架构不变。

## ADDED Requirements

- **REQ-02 适用性判定**：以当前独立 Noul 回答的 `probability` 为适用性依据，提供可配置最低值 `skillMinProbability`，默认 `0.5`，合法值为 `[0, 1]` 内有限数。`p ≥ skillMinProbability` 才有推荐资格，恰等于阈值时保留。缺省旧配置使用新默认值；非法配置失败，不默默修正。`confidence` 不参与筛选或排序。此次通过插件配置提供阈值，不增加专用 Web 控件；现有数量表单保存不覆盖阈值。
  - 验收：默认值下 `0.49` 排除、`0.5` 和 `0.51` 保留；阈值 `0` 保留所有合法概率，阈值 `1` 仅保留 `p=1`；高 confidence 不能挽救低 probability。
- **REQ-03 零推荐是成功结果**：对非空目录完成有效判断、但没有候选达到阈值时，发布一条具有零项 entries 的正常 Session 目录消息，说明本次没有技能达到推荐条件，并保留完整目录和原生加载入口。操作回执明确为“无适用推荐”，不能记为“已展示、无新增”。措辞仅描述本次判断，不断言客观上绝无适用技能。之前可见的摘要不删除。
  - 验收：八项均为 `0.01` 时，本次 entries 为 `[]`、没有技能名称推荐，判断成功且有独立可识别回执；主模型可继续任务，不出现 Retry/Cancel。无新用户请求且目录未变的后续普通步骤不重复判断或重复发布；正常 Session 回放保持此行为。
- **REQ-04 校准与交付证据**：使用已有历史候选分数和独立任务真值验证所选默认值，另用无费固定输入验证机制与临界值；两类证据分别报告。维护中的评测分析器按当次记录的选择参数核对新结果，保留旧记录原有的无阈值分析规则，不重写历史报告。源码行为和 GitHub 安装入口所加载的 tracked `runtime/` 行为一致，相关中英文 README 同步说明数量上限、最低概率、空结果和恢复入口。
  - 验收：历史 15 次所需项评分观察全部保持入选、全无关八项无一入选；报告数据范围及未验证项，不宣称新模型运行或普遍准确率。构建产物加载和直接相关回归检查通过。

## MODIFIED Requirements

- **REQ-01 推荐数量是上限**：
  - 之前：完整目录内所有 model-invocable 候选按概率降序排序，直接取前 `skillLimit`（默认 5）；低至 `0` 的概率仍可进入推荐。随后按当前可见目录中的名称去重。
  - 现在：先排除不满足 REQ-02 的候选，再按概率降序、原候选顺序打破平局，最多取 `skillLimit` 项，最后按可见目录去重。可选择 0 至 `skillLimit` 项，不用不适用候选补足上限，也不因去重后出现空位而从后续候选补位。
  - 验收：一项 `0.95` 加七项 `0.01` 时只选择前者；多于五项合格时仍只取五项。选择非空但全部名称已展示时，沿用“无新增摘要”回执，不新增目录消息，也不改记为零适用推荐。

## REMOVED Requirements

删除“低概率技能仍有资格被补入前 K 项”的技能推荐行为。无工具、原生加载能力、目录恢复能力或已有持久记录被移除。

## 保持不变的行为

- 只在现有 live Web root Agent、功能启用且原生 skill 工具可用等既有条件下选择；功能默认关闭。初始空目录、缺失任务上下文、不完整快照和不适用调用范围沿用原流程，不伪造判断或分数。
- 只向判断服务发送当前 model-invocable 技能的名称、描述和既有有界任务上下文；不读取或发送技能正文，不增加判断请求种类或模型调用次数。
- 新直接用户请求或目录变化重新选择；普通工具步骤不重复调用。可见摘要去重、目录替换后的重新检查、回放和其他作用域保持既有语义。
- 原生用户显式调用和 `skill` 按名称加载保持可用，即使目标未被推荐；`skill_catalog` 返回完整的当前 model-invocable 目录，不再调用 Jev。技能的 model/user invocation 权限不变。
- glob 的候选、低概率保留、顺序、数量、PTC 展示和恢复行为完全不变。

## 输入、默认值、顺序与优先级

输入保持原来的独立 Noul 候选回答；协议校验先于业务筛选。每次开始判断时读取技能上限与阈值；人工重试读取最新配置和候选，与现有上限更新规则一致。当前成功尝试使用该次读取的配置，不因等待期间的设置变化而混用两个阈值。

`skillLimit` 仍是正安全整数，默认 5；候选最低概率默认 `0.5`。两者独立，不能以把 `skillLimit` 设为零替代适用性判断。用户选择更宽松的0.5作为默认值；历史样本中的4次非所需项保留是已知结果，不把这次修复解释为消除所有非所需推荐。

先有效性检查，再最低概率筛选，再稳定排序，再数量上限，最后可见名称去重。零适用推荐与非空选择的去重为空分别记录；旧消息保留且原生显式调用不受推荐排序覆盖。

## 失败与回退

判断失败、回答不完整、取消或未采纳沿用现有 Jev Retry/Cancel 与调用终止语义，不能产生成功的零推荐消息或回执，也不静默发布完整目录。成功但全不适用不触发重试。初始空目录不发请求；重试刷新为空目录仍保留原有不可完成当前判断的错误处理，不虚构一次成功的零推荐。

输入或结果持久化失败仍按共享服务处理；回执失败不得触发重新执行来掩盖失败。既有开关、卸载和中断行为不扩展。

## 端到端传递

原生 pre-step 目录入口 → 既有 Jev 请求、协议校验与判断记录 → 适用性筛选与排序 → 正常 Session 中的增量目录或零项目录 → 主模型继续任务，按需调用原生 `skill` 或完整目录恢复工具。

辅助判断、业务回执与模型可见目录分别保留原来的存储职责。新发布目录的 Session 元数据记录当次有效最低概率和数量上限，供已有评测消费者核对实际选择规则；不通过解析回执的人类说明来推断配置，也不把本次设置追溯应用到旧记录。零项目录的内容和当前完整目录标识可由正常 Session 回放恢复，不新增 Session event 类型、不重写历史记录。

## 对外契约

新增插件配置 `skillMinProbability`，默认 `0.5`、含端点范围 `[0,1]`，仅约束 skill-selection。现有配置的技能数解释为最多数量；Web 数量表单仍只编辑原有数量字段。新的空目录消息与回执明确表达本次无适用推荐；`skill-catalog-no-new` 继续只表达有选择但摘要均已可见。既有原生工具参数和返回值、共享 Jev API、glob 输出与历史记录读取不变。

## 非目标

不加入 Tool Search、重新设计检索或完成核查、改变审批、修改 DSH 核心或用户 profile。不运行新付费模型评测，不为模型 confidence 设置业务门槛，不承诺通用准确率、成本收益或任务成功率。本任务授权提交、推送、创建 PR、等待必要 CI 并合入 main；不包含清理或新增设置界面。

- 已确认：用户已选择可配置阈值默认0.5、等号保留并继续实施。用户要求允许零推荐、以正负案例校准判定、保留相关推荐和原生加载/目录恢复，并授权本地 bug-fix 和 Delta Spec。工作区独立、实现交 Sol、本次续办授权提交、推送、PR 与合入 main；新增付费模型调用未授权。
- 代码事实：技能资格筛选、成功零目录与独立回执、可选选择元数据及直接消费者均已交付。完整本次验证见[决策记录](decision.md#verification)：Host/Client typecheck、4个相关文件68项、Python两模块17项、官方0.2.1-alpha.3正式安装与Web、构建后根runtime探针、84个分发文件一致性、网站及PR CI通过。远端main文件树与已验证PR head一致。
- 校准事实：历史 [公开评分](../../../../../docs/testing/2026-10-02-completion-skill/receipts.json) 与 [结果](../../../../../docs/testing/2026-10-02-completion-skill/results.json) 加上本地历史批次的research-one冻结真值（原始本地证据未公开）、research-two冻结真值（原始本地证据未公开）交叉核对，共128次评分，15次所需项为0.90–0.97，113次非所需项为0.01–0.58。全无关八项均为0.01。p≥0.5保留15次所需项和4次非所需项；p≥0.8保留15次所需项、无非所需项。这是同一批历史数据上的候选阈值比较，没有独立留出集、边界附近真实样本或跨模型保证。“非所需”来自任务真值，不等于证明其对所有任务毫无帮助。
- 未决问题：无。已有授权覆盖的本地实现、必要验证、提交、推送、PR 与合入 main 已完成；不包含新增付费模型调用或工作区清理。
