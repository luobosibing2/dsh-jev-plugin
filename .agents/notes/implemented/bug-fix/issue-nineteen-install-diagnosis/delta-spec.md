# REQ-JEV-COMPAT 增量规格

## 目标与范围

解决当前插件在旧 DSH 上因缺少 WorkingDirectory 服务而无法完整激活的问题。目标宿主为 `0.1.7-rc.1`、`0.1.7-rc.2`、`0.2.0-rc.1`、`0.2.0-rc.2` 和 `0.2.1-alpha.2`。本次包含必要兼容代码、直接相关回归验证、发行依赖声明、运行产物和安装说明。

## ADDED Requirements

- **REQ-JEV-COMPAT-01 旧宿主运行**：当前插件在上述五个已发布宿主的标准 Web profile 中通过官方安装器安装后，全部九个 Host 组件激活；技能选择、文件排序、指令检查及其余现有功能仍可按其已发布语义运行。
  - 验收：每个目标宿主加载最终安装包，全部九个 Host 组件激活；直接相关的已启用功能执行完成，不因版本差异等待不存在的服务或调用不存在的 API。
- **REQ-JEV-COMPAT-05 主分支交付**：用户在本地验收后明确授权推送 MR 并合入主分支。提交完整产品改动，通过 PR 将已验证文件交付到 GitHub `main`；实际合并后同步本地决策与整组文档生命周期。
  - 验收：PR 状态为 MERGED，远端 main 包含交付文件；合并后的文件与验收版本一致。报告实际检查状态，不把没有 PR checks 写成 CI 通过；本地任务文档保持私有。

## MODIFIED Requirements

- **REQ-JEV-COMPAT-02 工作目录**：技能候选和指令操作证据使用所属 Session 或 Agent 的原生目录，按 Session 或 Agent 隔离；没有设置目录时保持各消费者既有默认规则。
  - 之前：技能选择与指令检查要求宿主提供 WorkingDirectory，旧版本对应组件不能激活。
  - 现在：宿主提供原生目录服务时，读取它管理的实时目录；旧目标宿主未提供该服务时，使用该宿主原生工具实际使用的 Session 目录。无 Agent 的已有调用保持原有目录规则。
  - 验收：旧宿主在两个不同目录的 Session 中取得各自技能与指令；alpha.2 的原生目录切换后，技能选择和指令操作证据跟随新目录，不能退回最初目录。
- **REQ-JEV-COMPAT-03 支持声明**：只有完成目标版本的兼容验证后，安装包才扩大 DSH peer 支持范围；构建依赖继续使用明确的开发基线。
  - 之前：根包和 workspace 包的 DSH peers 精确声明 `0.2.1-alpha.2`。
  - 现在：安装声明覆盖 `0.1.7-rc.1` 至 `0.2.0-rc.2` 的已发布目标范围，并保留 `0.2.1-alpha.2`。本次不声明 `0.2.1-alpha.1`、低于起点或高于已验证终点的版本。只有 alpha.2 存在的可选目录能力不得造成旧宿主安装或加载失败。
  - 验收：最终根安装包和 workspace 安装包允许五个目标版本；明确未支持的版本仍被兼容检查拒绝。两种包的声明一致，开发依赖未被无界放宽。
- **REQ-JEV-COMPAT-04 完整发行内容**：源码兼容改动与 GitHub 安装使用的运行产物、包清单和双语安装说明共同交付。
  - 之前：当前 runtime 与说明仅覆盖 alpha.2。
  - 现在：最终安装包包含与修改后源码一致的 runtime 和配置补丁，说明支持版本以及旧 Session 目录与新版实时目录的行为。
  - 验收：构建与类型检查通过，安装文件与本次生成产物一致，英文和中文说明与实际支持范围一致。

## REMOVED Requirements

无。原生工具、Session 记录、Jev 业务功能和用户授权要求不删除。

## 保持不变的行为

十二个 Jev 功能默认关闭；功能启用仍由现有设置控制。判断请求、回答校验、账本、回执、重试与取消、业务采用和原生授权继续使用原有语义。当前目录能力的兼容处理不得改变模型或 API 通道、自动重试、权限或原生工具结果。

## 输入、默认值、顺序与优先级

存在原生目录服务时，以它给出的实时目录为准；只有旧目标宿主缺少该服务时才使用旧宿主的目录来源。Agent 调用不能误用另一个 Session 的目录，存在明确 Session 目录时不能改用全局进程目录。旧宿主目录未设置时，技能和文件查询保留 undefined 给原生 provider 选择默认目录；指令操作保留既有进程目录默认值。现有 Agentless 调用和配置默认值保持。用户要求的五个宿主是本轮支持目标；alpha.1 与未来版本不因位于宽松语义版本范围而自动纳入。

## 失败与回退

原生目录服务的读取、初始化、权限或取消错误沿用其错误语义，不把错误当作服务缺失后使用旧目录。旧宿主遵循原生目录默认规则，不构造另一个 Session 的路径；原生 provider 解析失败时沿用其失败语义。兼容验证失败时先修复可达的实现问题，正式声明保留原支持范围，直到该验收通过。

## 端到端传递

用户的目标宿主与官方 profile 安装器接收插件包；包内补丁激活九个 Host 组件；技能选择和指令检查使用与原生工具一致的目录获取候选和证据；现有 Jev 判断、记录与本地采用继续完成。alpha.2 原生目录切换后的新目录沿同一路径进入请求与证据。

## 对外契约

扩大插件安装兼容声明，不新增用户操作、工具、配置开关或公开兼容 API，不改变 Session 格式或 Jev 持久化格式。支持范围依据本次五版本验证；Host 激活、确定性业务验证、浏览器验证和真实模型质量分别报告。

## 非目标

不修改 DSH、Mu、Cua 或插件市场；不新增原生工作目录工具，不模拟旧宿主未提供的目录切换能力。不修改真实用户 profile，不使用付费模型、不发表单独的 Issue 评论。本次测试不承诺未来 DSH 或未经验证的平台兼容性；本地验收后的 PR 推送与 main 合并属于用户追加授权。

## 决策闭合

- 已确认：用户明确授权补兼容代码，覆盖四个旧目标版本并保留 alpha.2；测试通过后才扩大正式依赖范围，随后推送 MR 并合入 main。
- 实施前代码事实：技能选择和指令检查必需注入 WorkingDirectory；该服务只在本轮目标中的 alpha.2 提供。实验放宽声明后，rc.1 和 rc.2 旧宿主均只激活七个组件，两个目录消费者等待该服务；alpha.2 九个组件激活。
- 未决问题：无。旧目录来源以目标宿主原生工具实现为权威，由实现检查解析；若发现无法保持现有功能语义的其他 API 差异，回报主代理解决，不能静默减少功能。
