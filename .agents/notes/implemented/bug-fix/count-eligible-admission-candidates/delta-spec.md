# REQ-JEV-ADMISSION-COUNT 增量规格

## 目标与范围

修复通用日志准入将保留分组计入候选上限而过早跳过判断的问题。仅改变通用候选数量限制的统计对象；实现位于独立 Jev 插件，相关说明、测试和 tracked runtime 同步。该规格在本地实现完成后按用户要求补写，合并前补齐真实环境验证。决策理由见 [Decision](decision.md)。

## ADDED Requirements

无新增产品能力。

## MODIFIED Requirements

- **REQ-JEV-ADMISSION-COUNT-01**：通用日志的数量上限只统计最终可供判断的候选块。
  - 之前：所有分组超过 `maxGeneralBlocks` 即放弃，即使首尾或其他分组必须保留。
  - 现在：首尾及其他保留分组不占名额；默认上限 48，候选数不超过配置值时返回完整候选集合，超过时返回 `undefined`，放弃本次通用过滤。
  - 验收：超过 48 个总分组但不超过 48 个候选时仍能进入判断流程；48 候选允许，49 候选放弃。

- **REQ-JEV-ADMISSION-COUNT-02**：用户可见的配置说明与候选计数一致。
  - 之前：设置标签使用命令块数量上限，未明确排除保留分组。
  - 现在：中英文标签及说明明确限制的是候选；外部配置键、默认值和验证范围兼容已有配置。
  - 验收：现有 `maxGeneralBlocks` 配置继续有效，双语说明不再将总分组数作为上限统计对象。

## REMOVED Requirements

无。

## 保持不变的行为

- **REQ-JEV-ADMISSION-COUNT-03**：保留首尾、不可分类块和原有保护内容；仅判断既有噪声规则产生的候选，保留文本仍以完整原文及行号通过 `retainedEvidence.chunks` 输入 Jev。
- **REQ-JEV-ADMISSION-COUNT-04**：`maxRequestChars` 继续约束完整序列化请求。必要时减少提交候选，未提交候选继续保留且不作为删除其他候选的已展示证据；必要保留证据或一个完整候选无法容纳时不发语义判断。
- 测试日志分支、分组、默认关闭、原文存储、概率门槛、超时、未知回答、取消、失败及原生 Host 后处理均保持现有行为。

## 输入、默认值、顺序与优先级

输入仍为完整当前工具日志和现有配置。空日志返回空候选。`maxGeneralBlocks` 默认 48，既有最小值 3 和最大值 1000 不变。先形成既有分组并应用保留规则，数量限制作用于剩余候选；之后仍执行请求字符预算。任一限制未通过均不得凭本次判断删除日志。

## 失败与回退

候选超过上限返回 `undefined`，原结果继续原有流程。请求预算不足或判断失败沿用既有保留行为，不新增截断、摘要、重试或异常策略。

## 端到端传递

顶层工具执行结果进入原有 `tools/post-execute` → 通用候选筛选及数量限制 → 完整请求预算 → Jev 判断与采纳检查 → 原有保存和输出流程。模型可见结果以持久 Session 记录为准；Jev 记录用于确认实际提交候选和保留证据。GitHub 安装加载的根 `runtime/` 与源码同步。

## 对外契约

配置键、默认值、HTTP 请求协议、持久记录格式和插件入口均不变。大量保留分组不再阻止合格通用日志进入判断；模型是否选择省略仍由原有答案及门槛决定。

## 验收示例

| 场景 | 给定 | 当 | 则 | 覆盖需求 |
|---|---|---|---|---|
| 大量保留块 | 超过 48 个总分组、仅 1 个噪声候选 | 以默认上限筛选 | 返回该候选 | REQ-JEV-ADMISSION-COUNT-01 |
| 边界允许 | 48 个候选，另有保留分组 | 以默认上限筛选 | 返回 48 候选 | REQ-JEV-ADMISSION-COUNT-01 |
| 超限放弃 | 49 个候选 | 以默认上限筛选 | 返回 undefined，不进行本次通用过滤 | REQ-JEV-ADMISSION-COUNT-01 |
| 首尾保护 | 首尾都符合噪声特征，内部有候选 | 筛选并生成输出 | 首尾不进入候选且原文保留 | REQ-JEV-ADMISSION-COUNT-03 |
| 保留证据 | 51 总分组、24 候选，完整请求能容纳 | 原生工具结果触发准入 | 判断请求含 24 候选和保留原文，输出保留保护内容 | REQ-JEV-ADMISSION-COUNT-01、03 |
| 请求预算 | 候选数量合格但请求过大 | 执行既有预算处理 | 减少候选且保留未提交原文；无法容纳必要证据则不调用 | REQ-JEV-ADMISSION-COUNT-04 |
| 配置说明 | 既有配置键及双语设置 | 构建与安装 | 配置有效、说明明确为候选上限 | REQ-JEV-ADMISSION-COUNT-02 |

交付验收还要求本机官方 DSH 安装和启动冒烟通过、构建产物一致，并执行真实主模型和真实 Jev 的本地任务：日志须超过 48 总分组且候选不超限，确认真实判断请求、保留证据、持久结果及任务事实一致。模型选择全部保留是允许的；不得以 HTTP 成功或最终回答代替上述证据。必要自动回归通过后才合入 `main`。

首轮 CI 在未改动的共享发现测试中暴露 1 秒轮询等待异步关系处理的同步问题。作为验证阻塞修正，测试等待实际收据持久完成后继续检查原有关系、接收者和替换断言；不得弱化断言、增加重试、提高超时或修改共享发现产品行为。这是主代理根据 CI 证据选择的测试修复，不是候选计数产品需求的扩展。

## 非目标

不改变 DSH 底座、上下文预算、输出预算、分组算法、测试日志逻辑、请求协议或模型策略；不承诺真实模型普遍准确率或稳定节省比例，不修改用户 profile。

## 决策闭合

- 已确认：候选计数语义、48／49 边界、保留证据继续输入，以及真实测试通过后合入主分支均来自用户授权。
- 代码事实：原实现的总分组检查在保护过滤前；请求字符预算有独立的候选缩减和无调用路径；根 tracked runtime 为安装入口。
- 未决问题：无。
