# REQ-JEV-EVAL 增量规格：DeepSWE 配对评测接入

本规格描述 deepseek-harness-jev 的评测能力，当前为 implemented，PR #4已合入main。用户已授权 Sol 实现与验证、真实 DeepSeek/Jev 配对与glob案例验证，并于2026-10-01最新授权整理本轮glob实验及测试管线、创建一个commit并推送，随后更新现有网页。本次公开范围为管线源码、人工合成案例和脱敏结果；原始运行目录及其他私人实验不公开。决策理由见 [Decision](decision.md)。

## 目标与范围

让维护者用固定 DeepSWE 任务，对同一 DSH Agent 的 Jev 关闭组、日志筛选组和完成核查组进行可复核的配对评测，分别观察独立测试结果、运行成本和实际功能采用。测试与报告归 deepseek-harness-jev；DeepSWE 拥有原始任务与测试判定，Pier 拥有隔离环境和 trial 执行，DSH 拥有 Agent、工具、Session 和原生权限流程。

范围包括专用 profile 的兼容性验证、Pier 到 DSH 的适配、三组配置、配对运行及恢复、补丁和原始证据收集、离线汇总、使用说明。首次付费预检只运行 baseline 与日志组；完成核查组提供独立运行与验证能力，进入真实实验仍需单独明确批次与预算。本次交付包含本地实现、必要非付费验证和已获授权的首个真实配对预检；具体冻结条件见 Alignment。

最新交付增加已完成六类glob实验的公开依据与可从新检出使用的维护者管线，并把结果接入现有中文文件排序页面。固定历史实验与整理后的管线分别标识，不能用当前main版本或新脚本哈希替换原实验产物。用户授权本任务的一个commit及功能分支推送；目标分支合并须有明确授权，网页源码就绪不等于GitHub Pages已部署。

## ADDED Requirements

- **REQ-JEV-EVAL-01 固定实验身份**：每个批次在执行前固化任务清单及其选择规则、任务版本和 checksum、重复次数、组别、调度顺序、DSH/Pier/插件版本、插件产物哈希、镜像 digest、运行时版本、模型路由/模型标识/推理设置、Jev 连接的非敏感配置、权限/工具目录、上下文/压缩/spill 设置和预算。固定输入相同才能被归入同一实验条件。服务只提供浮动模型别名时，记录这一限制和运行时间，不宣称服务端模型可完全复现。
  - 验收：有效清单可在不执行 Agent、不调用模型的情况下检查并展示计划；缺少必填输入或本地可发现的配置不一致时，在启动收费执行前明确失败；外部版本确认只能在准备阶段取得时，确认失败不得进入 Agent 阶段。
- **REQ-JEV-EVAL-02 三组同条件配置**：baseline、日志组和完成核查组安装相同插件产物。baseline 的固定产物全部功能关闭；日志组仅启用 output-admission 与 test-log-admission；完成核查组仅启用 completion-check。实验组之外的配置相同，组名和隔离目录等运行身份差异可以不同但必须记录。所有功能参数采用固定产物的现有默认值并展开记录；本次不增加自动调参或组间不同阈值。三组专用评测 profile 均禁用不参与本轮的 jev-selection Loader 行，并记录这一有效模块配置；保留同一插件产物和该版本的完整开关值，不修改产品注册语义。
  - 验收：组别差异只包含预定开关与运行身份；首次预检清单只有 baseline 和日志组。无插件与全部关闭的受控预检确认没有额外 Jev 调用及模型可见内容差异，不将时间戳或会话 ID 当作行为差异。
- **REQ-JEV-EVAL-03 正式 DSH 入口和真实挂钩**：使用专用隔离 profile，经支持的 dsh 应用入口启动已注册 root Agent；任务作为正常直接用户消息进入。目标版本优先采用插件声明的 DSH 0.1.7-rc.2，不根据本地较新 DSH 源码假定兼容。必须在主模型启动前验证清单明确指定的权限模式及必要服务、配置和所测挂钩在该组合中可用；workspace-write 要求完整沙箱强制执行，用户授权的 danger-full-access 明确记录不受 DSH 沙箱限制，并检查实际可执行性；缺失时明确阻止该组执行，不能以零次触发假装接入成功。通过 profile 组合可满足时允许配置补齐；需要修改产品语义、DSH 或更换宿主模式时返回主代理对齐，不静默切换。
  - 验收：受控任务经过实际 DSH 工具与停止流程，在 baseline 不产生 Jev 判断；启用组产生可与该 Session 关联的实际判断及采用/保留记录。模拟模型验证只证明集成，不作为真实模型效果证据。
- **REQ-JEV-EVAL-04 独立隔离与判分**：同题各组使用相同初始代码、原始任务指令与资源条件，每次运行使用独立工作区、profile、Session、ledger 和插件缓存。参考答案、隐藏测试、先前结果与他组补丁不得进入 Agent 可读挂载或模型上下文。严格配对专用 profile 两组均关闭 web_search/web_fetch；外层网络仅允许固定推理和npm端点，不通过搜索后端获取公开任务答案或隐藏测试。Agent 修改经收集后，由 DeepSWE 的独立干净 verifier 判分，Jev 判断和 Agent 自述不能覆盖 verifier 输出。
  - 验收：Agent 的可用材料不含评估专用内容；两个组互不共享可写状态；同一补丁可在固定 verifier 条件下重新评分而不重跑主模型。环境准备与模型调用使用显式所需网络权限，Agent 做题阶段不依赖读取公开答案站点。
- **REQ-JEV-EVAL-05 完整生命周期和补丁**：从准备、Agent 执行到验证记录分阶段时间、退出原因和产物。正常结束要求当前受支持执行流程及所测插件操作已稳定；完成核查排入的合法补做必须执行或被明确记录为未执行，不能在首次 idle 或出现第一份回答时提前收集。原生停止、取消和预算上限仍优先，不绕过它们等待补做。收集指定任务工作区相对固定 base 的实际修改，包括未提交修改和新文件；保持用户任务代码含义，不按其他分支最近提交时间切换代码，不静默丢弃无法纳入的修改。模型自行提交的修改仍包含在最终补丁中。
  - 验收：普通结束、完成核查补做、超时、异常及补丁收集失败均有可辨识记录；在有可用补丁且 verifier 可运行时仍保存独立评分，同时保留终止原因。无法收集时明确缺失，不伪造空补丁作为成功收集。
- **REQ-JEV-EVAL-06 无人协助和权限**：这轮不提供人工解题、模拟专家回答或自动批准。原生用户问题或插件 Retry/Cancel 请求出现时，记录 needs-human 和问题类型，按受支持停止流程结束本次自主运行并保留证据；不无限等待、不把默认选项当作用户回答。仅在最终文本中提问但未发起交互请求的情况保存原始回答和停止事实，由独立测试判定，不用不可靠关键词分类覆盖状态。日志筛选失败沿用产品既有保留原输出策略。权限一致且固定，不启用 workspace-approval。用户最新已授权本次两组均采用 danger-full-access，容器仍使用默认 Docker 权限；其他实际人工请求仍按无人协助规则停止。
  - 验收：两个组面对同类原生提问均按同一策略记录与结束，不继续偷偷补答；有正常日志筛选回退时 Agent 按产品原流程继续。不能通过公开 DSH 能力辨识交互或稳定停止的组合不通过接入验收。
- **REQ-JEV-EVAL-07 配对调度与恢复**：每个任务、任务版本、重复序号形成对应组的配对；每次实际 trial 和重试均可单独定位。批次在观察结果前固定 AB/BA 顺序及并发上限；默认一个 Agent trial 执行，两个组交错且顺序平衡，避免同机两组竞争。恢复只补未终结的计划槽位或清单允许的重试，不覆盖先前运行，不把已完成成功或失败改成缺失再执行。任务结果、预算耗尽和 needs-human 不自动重跑；有明确证据的基础设施故障才能在预设次数内重试，默认不自动重试。不用胜负筛选下一次重复。
  - 验收：中断再恢复不会增加未约定的有效尝试，结果可追到原 trial；已启动但失去状态的运行记中断并先确认不再活动，不能并行重启同一槽位。多次运行保持单次粒度，不依赖不透明 attempts 聚合。
- **REQ-JEV-EVAL-08 证据与分别计费**：保留脱敏实验配置、身份/时间、补丁、DSH Session、Jev ledger、verifier reward/测试报告/原始输出、错误及缺失说明。记录主模型与 Jev 各自实际可获得的调用、输入/输出/cache usage、延迟和费用来源；重试与失败调用费用计入实际消耗，缺失为未知，显式零与未知不同，缓存命中不等于 HTTP 请求。不扫描任意同名字段累加，不以日志词数作为 token，不将估算计价写成账单实付。
  - 验收：汇总值可追溯到逐次权威记录；删去一个请求 usage 后报告对应完整性不足，而非成本更低。保留模型 usage 的字段语义，推理 token 属于输出总量时不再重复相加。
- **REQ-JEV-EVAL-09 功能参与程度**：报告按功能区分符合条件、判断、采用/保留/回退和最终任务结果。日志组保留可验证的删减量、原始结果恢复引用与实际完整日志回读证据；完成核查组区分提出补做、补做排入、实际执行及最终验证。仅有 ledger 调用或补做排入不等于效果已经发生；无法从现有公开记录得到的计数标为不可观测，不能补零或为本次评测静默修改插件协议。受控预检须证明关键路径可观察，实际题未触发是有效零参与样本。
  - 验收：未触发、调用后全部保留、超时回退和实际删减四种情况可区分；没有送达/执行证据时不报告“纠正成功”。若关键采用与输出证据无法取得，标明验收不通过并说明缺口。
- **REQ-JEV-EVAL-10 配对报告与分母**：主评分保留官方 reward、F2P/P2P 原始计数；reward=1 表示独立测试全部通过，不代表正常退出、无需人工或代码质量全面合格。另报正常结束且无需人工的完全解决数量、各种退出原因、基础设施失败率和计划完成度，不能将拿到 reward=1 的超时运行伪装为正常完成。逐次结果完整保留，按题先汇总各组重复再做配对；同时列共同可判分样本与缺失数量、敏感性口径，不能只发布条件筛选后的比例。报告 F2P 差、P2P 回归、Agent 时间和 trial 时间、主模型/Jev/总成本及每项完整性。成本报告包含全部实际尝试及失败消耗；仅双组都解决的成本可作单独条件性分析。使用任务级不确定性表达，不能把同题多次当成独立新题。
  - 验收：报告分母等于所列样本；排除两题时胜负数和平均值同步改变。不同退出状态与 verifier 结果同时可见；无配对或 usage 不完整仍可输出不完整报告，不宣称结论闭合。报告不以 partial 替代 F2P，不挑最新/最好运行。小样本、区间跨零、缺乏实际参与或严重缺失时给出无法确认收益的结论，不等同证明无害。
- **REQ-JEV-EVAL-11 执行控制与可复现说明**：提供计划检查、按冻结批次运行、恢复、对已保存补丁重评和离线汇总的可发现入口，说明实际命令及前置条件。计划检查和离线汇总不调用模型；真实执行必须由操作人明确选择，使用独立凭据供给及明确预算，既有本机用户 profile 和私人 Session 不作默认输入。对可观测的上限在达到后停止新请求/新 trial，并通过支持的停止流程终止当前 Agent；无法准确实时计价时，在运行前说明支出上限的误差与在途请求费用，不能把事后统计冒充硬美元限额。缺少所要求的硬限额执行能力时拒绝该配置。
  - 验收：缺少真实运行输入时不给自动模型/预算；帮助与实际命令一致。默认不发布证据、不安装全局依赖、不清理共享 Docker 网络；只管理本批次拥有的资源。用户已授权实现和非付费验证，真实模型执行仍需明确输入与授权。

- **REQ-JEV-EVAL-12 可提交的glob测试管线**：公开管线提供显式输入下的准备、无模型检查、无模型入口预检、按固定顺序逐试次执行及离线结果检查/汇总。新检出不依赖本机路径、旧私人批次、预先安装的私人profile或旧运行目录；所需上游/运行时/插件产物/价格与预算由操作人指定。六类0/1/12/16/40/41候选各baseline/开启一次，真值与运行输入预先锁定。无自动收费整批入口、无人协助规则和停止追加规则保持；新实现不要求重跑既有真实模型实验。
  - 验收：无凭据且没有旧.artifacts时仍能准备及检查输入，缺失声明依赖明确报错；离线汇总支持缺失/未开始试次；无费用预检能构造12试次，付费入口未显式选择时不启动模型。
- **REQ-JEV-EVAL-13 公开历史实验依据**：公开报告和结构化结果保留全部6例12次、真实4次Jev/69候选、原输入锁/插件tar/版本/模型/镜像、逐组用量和峰价估算、目标排名与源码/恢复读取数、语义负例和零触发边界。人工合成相对路径及必要判断回执可公开；不得包含凭据、授权头、主机个人绝对路径、用户profile、完整原始Session、stderr/stdout或其他私人批次。原实验输入不覆写；新整理的代码标明并非当时一次性driver的逐字副本，旧版证据不证明当前main重新验证通过。
  - 验收：公开字段与指定原始证据逐项一致，包含nested目标第5及multi解析器诱饵第2；12/12结构通过不提升为通用准确率或DeepSWE收益；估算USD0.026908236与账单区分，公开文件可独立阅读且无本机链接。
- **REQ-JEV-EVAL-14 网页证据接入与提交**：沿用现有纯中文网站、文件排序详情和证据镜像方式，将六类真实观察、默认40/12、grep旁路、质量限制与公开报告/管线入口内联呈现；只更新相关功能的首页证据，不重设计或修改其他功能结论。提交仅相关源码/公开资料，以一个commit推送本任务分支，原始目录和本地规划不进入Git。Pages工作流覆盖新证据源；目标分支合并或部署须实测后才声称线上更新。

## 保持不变的行为

新安装全部功能默认关闭；插件仍经 DSH 扩展点工作，模型可见效果由 DSH Session 记录，辅助判断由 Jev ledger 记录。原生 spill、上下文压缩、权限与工具验证继续生效。完成核查对普通请求最多补做一次，不能由 runner 追加 continue 绕过次数限制。主模型和 Jev 都看不到最终 verifier 的隐藏答案；运行间不共享纠正、缓存或先前补丁。DeepSWE 原始评分及题目不作适应性修改。原有完成漏检、跑偏送达未验、共享重复、审批误判和测试日志缩减证据不足的限制继续有效，直到对应新证据足以更新。

## 输入、默认值、顺序与优先级

运行必填输入为固定组件/任务版本、明确任务 ID 清单、两组或三组中的本次比较、每题重复数、主模型及推理设置、Jev endpoint/model、所需凭据来源、Agent/verifier 时限、其他声明预算、批次支出约束及计价完整性政策。服务凭据不出现在实验公开配置。没有显式 step/token 上限时必须记录为未设置，不能声称受该类上限控制；至少有可执行 Agent 时限和有限批次规模。实际费用硬上限是否可执行由所选 provider 的能力决定并预先展示。

默认实验条件为 baseline 对日志组、插件现有参数、单 trial 并发、无自动失败重试、无人工协助、不发布原始证据。首次真实预检建议为 3 题×2 组×2 次；20 题×2 组×3 次只是后续规模建议，不是已选清单或付费授权。首批具体题目在冻结前确定，按可运行性和自然功能覆盖选择并记录；正式题不得因观察本批胜负而重选，预检结果不得混入正式收益结论。

原生权限和用户停止优先于继续做题；预算终止优先于插件补做；插件现有保留/回退语义优先于评测追求删减量；独立 verifier 输出优先于模型或 Jev 自述。任务级判分、运行状态和证据完整性分别表达。配置或已记录组件发生变化，产生另一个明确实验条件，不与原条件静默合并。服务端共享缓存未能控制时记录限制和组间顺序，不承诺完全独立缓存。

## 失败与回退

- 配置缺项、依赖服务缺失、预期挂钩未接入或权限条件不同：准备失败，禁止把该运行列为有效处理组；未产生模型调用时如实记录零调用。
- 日志筛选模型超时、无可用答案或无法保存完整原文：使用现有产品保留原输出路径，记录回退；不改为人工重试或降低阈值。
- 正常 Agent 工具错误、错误实现、Agent 引起的构建失败、补丁不能应用：保留任务失败及测试证据，不因 P2P 全零自动归为基础设施失败。
- 实际原生问题/Retry/Cancel：needs-human，记录并受控停止；文本提问本身保留为 Agent 输出，不推断发生了真实用户问题事件。
- 超时、预算耗尽、用户取消、进程中断：保持实际终止原因，收集可获得证据；已有有效补丁仍可重评，评分不覆盖终止原因。
- 镜像下载、环境构建或 verifier 自身故障：附可定位证据后归类基础设施失败；无法判断归因时标为未知，不从报告中消失。
- 部分证据或 usage 缺失：输出不完整报告并标识受影响指标；不伪造 Session、费用、耗时、测试数或缓存命中。

## 端到端传递

操作人提供并冻结实验清单 → 准备检查确认版本、资源和配置 → Pier 为每个计划槽位启动隔离环境 → 专用 DSH profile 接收原始任务 → 现有插件读取开关并参与正常 Agent 执行 → 收集稳定或明确终止的工作区补丁及 Session/ledger → 独立 verifier 在干净代码上评分 → 以任务版本及重复序号连接两组证据 → 离线生成逐次、逐题和批次报告。

准备、执行、停止、收集和验证各阶段的身份与时间始终关联同一个实际 trial。Session 是模型输入与工具执行的证据，ledger 是 Jev 判断及采用回执的证据，verifier 是测试判定的证据；三者都不能替代其他两者。适配器不得通过首条回答或首次 idle 推断跨阶段完成。
