# Jev 与原生 Spill 预算协同

实际实现仓库是 `deepseek-harness-jev`；DSH 仅供只读核对。实施工作区为隔离工作区（位置未公开），分支为 `codex/jev-native-spill-budget`，基线为远端已核对的 `origin/main`、`c673f79298a29e7bcd45c9f09db217da253bbf4f`。实施阶段授权覆盖本地修改、必要验证与提交MR，用户另要求生成Delta Spec。后续[PR #48](https://github.com/luobosibing2/dsh-jev-plugin/pull/48)已实际合入main，完整合并与验证记录见[Decision](decision.md)。真实profile修改与付费模型调用未纳入本次实施。

Jev 仍在原生 spill-policy 裁剪前处理。先取得运行中实际生效的 `maxInlineTokens`，按宿主相同的内容估算规则检查 Jev 收到、尚未经该策略裁剪的模型可见结果。超过预算直接跳过本次 Jev 准入，包括判断调用和规则省略；结果继续交给原生 Spill。等于预算按 `<=` 通过，再应用已有最小长度、工具类型、任务材料等检查。不增加顺序开关，不硬编码另一份 12K 或 12500，不把 token 预算当成 Unicode 码点数。

保留完整 Jev 序列化请求预算、候选与保留证据完整性、超时、取消、任务版本 `canAdopt`、原文保存、恢复提示及净缩减条件。采用前，最终模型可见内容中的省略标记、恢复提示和外层结果也须计入宿主预算。本功能定位为预算内较长日志的任务相关性去噪；超预算结果留给原生 Spill，不据此宣称任务准确率、真实 token 节省或自然任务收益。

用户已确认：Spill 未加载或没有配置 `maxInlineTokens` 时，沿用现有 Jev 处理，不施加原生预算限制。`0` 是有效的有限预算，不属于未配置。已知无预算与无法可靠取得预算必须区分，不能把后者当作前者。

公开接口核查已闭合：七个兼容版本提供共享内容估算、真实插件运行实例、验证后的配置、事件可见性过滤和同步生命周期通知；可在 Jev 侧确认本次执行所见策略及执行期稳定性，无需改 DSH 或改变兼容范围。无法唯一可靠确定预算，或执行期间策略/上下文发生变化时，保守放弃本次 Jev 处理，原结果继续宿主流程；不能冒充已知无预算。已知无预算的原有 Jev 行为按用户选择保留。
