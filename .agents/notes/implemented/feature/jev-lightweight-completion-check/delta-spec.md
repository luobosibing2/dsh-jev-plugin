# REQ-JEV-LCC 轻量完成声明核查增量规格

本规格保留已确认的完整行为要求。代码、tracked runtime 与 HTML 已通过 PR #26 合入独立插件 main，必要的测试同步修复通过 PR #27 合入；最终 main CI 通过。[当前对齐](alignment.md)记录确认范围，[已实施决策](decision.md)记录取舍、合并与实际验证；线上部署状态单独记录。

## 目标与范围

- 目标：让 Jev 根据主模型已经提供的完成说明发现遗漏、未满足条件或前后矛盾，并在有限次数内让主模型补做或补充材料，减少为核查而整理长执行轨迹的成本。
- 产品范围：独立 Jev 插件的普通根 Agent `completion-check`、其主模型提示、设置入口、核查记录与用户提示。只处理当前 turn；原生 Goal 所有的 turn 不启动另一套完成补充循环。
- 代码范围：独立插件仓库 `deepseek-harness-jev`。通过已有 DSH 插件接口接入，不修改 DSH、Mu 或 Cua。本文的规划归属不扩展产品修改范围。
- 完成含义：报告显示任务满足用户要求，不等价于产物经独立验收。未测量此设计的判断准确率、自然任务收益或平均费用。

## ADDED Requirements

- **REQ-JEV-LCC-01 Todo 中的完成依据**：完成核查启用时，插件向主模型提供简短提示，要求更新已有 Todo 时在 `content` 中简述实际动作、产物路径或已执行命令及观察结果。失败、未完成、未验证内容如实保留。不强迫简单任务建 Todo，不新增字段或模型工具，不要求事件编号、独立证据报告或默认额外整理轮次。现有 Todo 的 `content` 和 `status` 保持不变；缺少固定“依据”字样不是拒绝 Todo 写入的理由。
  - 验收：启用后正常模型上下文含上述提示；关闭时不注入此提示；普通 Todo 写入仍按原 schema 接受，无需新增字段。

- **REQ-JEV-LCC-02 补充额度设置**：在现有 Jev 设置页提供“最多自动补充轮数”，按当前 profile 保存，默认 `3`。接受正整数；非法输入必须显示错误并保留此前有效值。它独立于完成核查开关和原生 Goal 的连续无进展轮数；修改次数不自动启用功能。
  - 验收：保存为 `2` 后的新 turn 最多自动补充 2 次，正常核查最多 3 次；另一 profile 的值不变；非法值不覆盖有效配置。

## MODIFIED Requirements

- **REQ-JEV-LCC-03 触发与当前 turn 范围**。
  - 之前：普通完成核查在停止 hook 运行，没有按本 turn 是否使用 Todo 过滤；证据从当前请求起点收集可见执行消息。
  - 现在：仅在功能启用、当前普通根 Agent turn 用过 Todo、主模型即将正常结束时核查。Todo 状态不要求全部 completed；Todo 写入本身不触发。当前 turn 没用 Todo 就跳过，前一 turn 的 Todo 不算。用过 Todo 后清空列表不把该 turn 改成“没用过”。用户中止、仍有待处理的新用户输入或已有待执行步骤时，不以旧状态发起补充。
  - 验收：无 Todo 的新 turn 即使上一轮有清单也不调用核查；本轮有 pending 条目仍核查；执行中的 Todo 写入没有 Jev 完成核查请求。

- **REQ-JEV-LCC-04 完整且轻量的输入**。
  - 之前：完成核查输入包含本请求的可见消息和工具记录，按字符预算从较新消息取舍，并用完整性标记限制采用。
  - 现在：提供当前 turn 的原始用户要求与该 turn 内适用的后续调整、完整最新 Todo、核查前最新最终回答，以及必要的判断规则和引用选项。当前 turn 的要求在补充期间保持；新增调整必须纳入。排除原始工具结果、完整执行轨迹、reasoning 和跨轮历史任务。插件自己的补充提示不作为用户新要求或新增授权。
  - 现在：只检查当前 turn，不自动关联跨轮任务。新一轮只说“继续”时，不补入上一轮要求；即使主模型自行把历史内容写入新 Todo，也不能把它当成本轮原始用户要求。无法从本轮材料判断时允许 `unknown`，不得伪称覆盖历史任务。最新 Todo 可为空，最新最终正文可为空；不得拿前一轮材料补位。完整原始要求若因上下文裁剪等原因不可获得，不以摘要冒充原文，应显示核查未完成并进入重试/取消处理。
  - 验收：当前 turn 的补充要求进入后续核查；原始工具记录与上一 turn 的要求不进入该请求；多个补充停止点总是采用最新 Todo 和最终回答。

- **REQ-JEV-LCC-05 两个选择题与结论含义**。
  - 之前：一次请求已有 assessment 与证据位置两个 choice 问题；矛盾归入 omission，unknown 被视为不可用结果。
  - 现在：一次请求继续只包含两个 choice 问题，共享同一输入。assessment 支持下表五种结论；focus 从插件生成的用户要求、Todo 条目和最终回答引用中选择。complete 可选择 none；整体材料不足可选择整体位置。未出现在 Todo 中的遗漏要求仍可通过用户消息定位。每次仅指出最关键的一处，不声称穷举所有问题，不追加生成式理由问题。
  - 验收：单次核查只有一次判定请求；两个答案能映射到合法结论与现有材料。有效 unknown 被作为业务结论采用，不弹技术重试。缺少答案、类型错误或不存在的引用按响应错误处理。

| assessment | 含义与限制 |
| --- | --- |
| `complete` | 所给报告显示要求已满足，未见明显遗漏或矛盾；不表示独立验证代码或产物正确。 |
| `omission` | 本轮要求未交代、明确未完成或用户规定条件未满足。不能擅自增加测试或交付条件。 |
| `contradiction` | Todo 状态、完成说明或最终回答前后不一致。不能据此宣称已定位真实代码缺陷。 |
| `needs-user` | 完成确实依赖用户尚未解决的选择或授权；可在原授权内更正的报告问题不属于此类。 |
| `unknown` | 所给材料不足，无法可靠判断；不等价于任务完成、失败或技术调用错误。 |

测试是否必须通过由用户要求决定。“运行并如实报告测试”可以通过报告失败满足；“修复并通过指定测试”在仍失败时属于未满足条件。此语义属于 REQ-JEV-LCC-05，不能以所有测试一律通过替代。

- **REQ-JEV-LCC-06 有限补充与复核**。
  - 之前：普通请求只有 omission 能保留一次自动补做机会；再次遗漏停止，unknown 进入人工重试处理。
  - 现在：omission、contradiction、unknown 在同一 turn 共用 REQ-JEV-LCC-02 的补充额度。omission 让主模型补上遗漏，contradiction 让它核对并更正，unknown 让它补充真实依据或说明。每次补充通过现有继续执行接口进入同一 turn，当前 Todo 保留；主模型按问题更新相关条目，再次停止时用最新输入复核。
  - 现在：初次核查不占补充额度；上限为 N 时，正常流程最多 N 次自动补充、N+1 次核查。默认 N=3。每个结论变化不重置计数；每次只补充最关键问题，并不保证 N 次覆盖全部问题。complete 正常结束；needs-user 停止自动补充并交用户决定；额度耗尽仍有问题则显示最后结论并停止。主模型补充不新增修改权限、不重做无关完成项、不强迫编造结果或改为 completed。
  - 现在：沿用现有持久记录与重复处理保护，刷新、恢复或重复处理同一补充不能重新获得已使用额度。新用户要求到来后不采用旧判断；先按原生流程处理新输入。技术失败或发送前预算拒绝不新消耗补充额度；已经实际请求主模型补充的轮数也不因随后核查失败而退还。
  - 验收：依次收到 omission、unknown、contradiction 可使用三次补充；第四次核查仍非 complete 时不再自动继续。中途 complete 或 needs-user 时提前结束。重复处理不产生重复补充。

- **REQ-JEV-LCC-07 超长输入处理**。
  - 之前：从完整可见历史中省略超出预算的消息，再因证据不完整拒绝采用结论。
  - 现在：发送前检查完整轻量输入。超过现有字符预算时不裁剪、不默认额外摘要、不把残缺输入交给 Jev 判完成；显示“核查材料超出预算，本次完成核查未完成”。允许用户调高已有字符预算后选择重试，重试重新读取完整当前材料和当前配置。预算检查拒绝不消耗补充额度。
  - 验收：超预算时没有判定请求或主模型补充；原材料保留。调高到足够预算后重试才发送完整输入。仍超预算时继续如实提示，而不是截断。

- **REQ-JEV-LCC-08 技术失败的重试与取消**。
  - 之前：接口失败或结果不可用时，现有交互等待用户选择“重试/取消”。
  - 现在：请求超时、接口错误、响应格式或引用验证错误明确显示“本次完成核查未完成”，保留主模型结果，并沿用现有“重试/取消”等待交互。重试读取当前输入及配置；取消结束本次核查，不把任务改写为成功或失败。REQ-JEV-LCC-07 的预算失败采用同一交互。技术失败不作为 unknown，也不触发主模型自动补做。技术重试不计入 N+1 的正常业务核查次数，不能把业务上限误报为包含人工重试的 HTTP 总次数。
  - 验收：错误后可见失败提示和两种选项，未选择前不自动继续；重试能使用修正配置，取消不再派发；错误前已有补充计数仍保留。

- **REQ-JEV-LCC-09 可追溯的提示与结果**。
  - 之前：插件把结论标签和所选记录引用组成提示，并保存判定与动作记录。
  - 现在：继续由插件用结论类别、所选材料原文和固定模板生成提示；编号由插件分配，Jev 不自由编造引用。记录实际核查输入、回答、采用与否、自动补充次数和结束原因。进入主模型的补充提示须能从 Session 记录重建；辅助判定沿用插件记录。保留主模型原始回答，不把后续核查装成发布前拦截。
  - 现在：用户能区分“报告核查完成”“发现问题”“材料不足”“调用或预算导致核查未完成”。若服务返回概率或 confidence，可保留为诊断数据，不显示为任务正确率。记录失败或动作状态未知时不宣称成功，也不以未知状态为依据重复补充。
  - 验收：提示中的原文与实际输入对应；补充与停止原因可查；旧结果不作用于变更后的要求；没有未经记录的模型可见核查提示。

## REMOVED Requirements

本次没有移除独立公开工具或 API。普通完成核查不再要求原始工具证据匹配、不再省略消息后继续发送残缺输入、不再把有效 unknown 当技术失败，也不再固定最多补做一次；这些完整替代行为分别由 REQ-JEV-LCC-04、05、06、07 定义。

## 保持不变的行为

- 所有 Jev 功能默认关闭、独立启用；不修改用户日常 profile、模型连接、凭据或既有功能选择。
- Jev 服务现有判定后端选择不变，本次不引入新模型或切换 provider。
- 原生 Todo schema、写入行为和 turn 生命周期不变。补充在同一 turn，下一 turn 依原生行为清空 Todo。
- 原生 Goal 的轮次、无进展计数与完成申请处理，以及跑偏提醒、阶段导航等其他功能不采用本次新的报告核查规则。共享函数不能使这些消费者静默改变。
- 用户权限、只读要求与原生停止/取消优先。核查不授予删除、修复、部署等额外权限，不创建验收 Agent。
- 不删除旧判定记录、历史测试材料或已提交的实验结论；旧实验不能作为本次语义效果已经验证的依据。

## 输入、默认值、顺序与优先级

- 输入仅覆盖当前 turn：用户原始要求及该 turn 内适用调整、最新 Todo、最新最终回答。保留要求的时间顺序，由 Jev 按后续明确调整理解当前任务；程序不额外调用模型抽取要求。跨轮省略属于已声明范围限制，不能谎称核查了整个历史任务。
- 没用 Todo 的 turn 先跳过；用过 Todo 则取完整材料并检查预算；预算通过才发送两个问题；验证回答后再决定是否补充。Todo pending 不代表自动失败，必须对照要求判断。
- 自动补充默认 3 次且可配置。现有输入字符预算默认 24,000、上限 1,000,000 不在本次调整范围；字符预算不是 provider 的 token 容量保证。设置及判断后端沿用当前 profile。
- 完整性检查覆盖实际发送的核查材料和必要引用，不能通过隐藏裁剪符合预算。没有最终正文时保留为空；没有当前条目但本 turn 用过 Todo 时保留空表，不引入前一 turn 的内容。
- 新用户要求、原生中止与执行状态变更先于旧判断采用；有效 complete 或 needs-user 优先于剩余补充额度。额度剩余不要求把轮数用完。
- 用户手动重试仅重试核查，不新建业务 turn 或重置当前 turn 已用的自动补充次数。

## 失败与回退

| 失败或停止原因 | 对用户及主模型的行为 | 计数与结果 |
| --- | --- | --- |
| 完整输入超出预算 | 超长提示，等待重试/取消；不自动摘要或派发 | 不新增补充次数，不宣称核查完成 |
| 当前 turn 原始要求无法完整获取 | 核查未完成，说明材料缺失，等待重试/取消 | 不以摘要替代完整要求，不宣称报告已覆盖要求 |
| 请求超时、接口、格式或引用错误 | 核查未完成，保留主模型结果，等待重试/取消 | 不新增主模型补充；已经使用的次数保留 |
| 有效 unknown | 额度内要求主模型补充依据；耗尽后显示最后结论 | 属于业务补充，不进入技术重试 |
| 用户取消核查 | 结束当前核查，不再自动补充 | 不把任务或报告标为成功 |
| 用户中止、输入变化或判断过期 | 遵循原生流程，不采用旧判断继续 | 不重置已用额度以重放同一动作 |
| 判定或补充动作记录失败、状态未知 | 沿用现有结构化失败处理，明确未确认状态 | 不宣称已成功采用，不盲目重复动作 |

没有自动回退到整段工具轨迹核查或额外摘要服务。恢复仍遵循当前输入、当前配置和原有用户授权。

## 端到端传递

用户在当前 turn 提出任务与调整 → 主模型在正常工作中按需维护 Todo 及完成依据 → 最终回答已显示 → 插件在停止时判断资格并组装完整轻量输入 → 预算检查 → 一次判定请求的两个 choice → 插件验证并记录结论及原文引用 → 正常结束、等待用户、或同一 turn 内注入补充 → 更新 Todo 与最终回答 → 再次核查。

模型提示通过现有系统提示注册能力提供；补充通过现有 Agent 继续执行能力提供，并保留原生 Session 记录。插件配置与辅助判定沿用既有配置、记录服务。不得为本变更创建新模型工具、独立任务状态服务或修改 Agent loop。

## 对外契约

- 新增可见的补充次数配置，默认由固定 1 次变为可配置 3 次；无 Todo 的当前 turn 不再完成核查。
- 正常输出新增独立 contradiction，unknown 的处理从技术重试改为业务补充；提示说明“依据报告核查”，不继续暗示已核对原始工具结果。
- 失败与超长采用已确认文案及重试/取消。用户可看到初始最终回答、核查提示及补充回答；不要求替换或隐藏早先回答。
- 不改变模型可用工具集合、Todo JSON 字段或 DSH 公共 API。配置与判定记录的消费者须一同适配，既有历史记录保持可读，不为了本次方案抹去历史。
- 实施交付时同步插件的中英文功能说明与配置文档；GitHub 安装入口使用的已跟踪 runtime 必须与源代码一致。此项属于已授权的本地实施与构建；不发布或修改日常 profile。
