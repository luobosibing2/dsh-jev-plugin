# REQ-LUNA：Jev / Luna Decisions 与双 API 接入增量规格

状态：implemented。完整最终规格已实施并通过适用验收；PR #11已实际合入main，交付与验证事实见同目录的 [决策记录](decision.md)。

## 目标与范围

用户在现有插件中选择 Jev 或 Luna Decisions。选择 Luna Decisions 后，用户可以使用 OpenRouter API 或 OpenAI 官方 Decisions API。业务功能继续使用共用判断能力，模型生成、工具执行、权限处理及各功能的判断题和采纳规则保持现有行为。

实施对象为独立的 `@dsh-jev/plugin`，仓库目录为 `deepseek-harness-jev`。范围包括判断连接设置、两种 Luna API 的请求与响应兼容、判断记录、阶段导航的连接有效性，以及实际安装产物。技能筛选、文件排序、跑偏监督、完成核查、原生目标增强、指令检查、消息路由、共享纠错、通用及测试日志准入、工作区审批、阶段导航均使用用户所选的判断连接。

本轮实施本规格并完成必要验证。用户已追加授权将接入与检验写入公开文档、代码合入main并同步官网实验结果；实际合并及官网发布已完成，状态为implemented。日常用户profile修改不在交付范围，真实模型验证与确定性接线验证分别报告。

## ADDED Requirements

**REQ-LUNA-001：选择模型与 Luna API 渠道。** 每个 profile 独立保存判断模型选择 `Jev` 或 `Luna Decisions`；Luna 独立保存渠道选择 `OpenRouter` 或 `OpenAI`。同一 profile 的全部已启用判断功能使用已保存的模型与渠道。设置页显示这两个选择以及对应的完整请求地址、请求模型标识、凭据引用和连接状态；选择 Jev 时仍保留之前保存的 Luna 渠道及连接。

验收：在 profile A 保存 Luna / OpenAI 后，A 的后续判断请求走官方 Decisions API；profile B 的已保存选择保持原值。重新打开页面及重启 profile 后，三套连接和当前选择仍可读取。

**REQ-LUNA-002：两种 Luna API 返回相同的业务答案语义。** OpenRouter 通过 `https://openrouter.ai/api/alpha/decisions` 请求 `openai/gpt-6-luna-decisions`；OpenAI 官方通过 `https://api.openai.com/v1/decisions` 请求 `gpt-6-luna`。两者均使用 Luna Decisions，不能用 Chat Completions、Responses 或其他模型代替。API 协议由用户保存的渠道确定，不能只按域名或模型名前缀猜测。

共用业务层以现有 Choice、Score、Noul 请求和答案含义为基础，各外部协议直接与这一基础转换。Jev 及 OpenRouter 请求保留其已支持的 System One 原生表示；官方请求使用官方 Decisions 表示。不得为了统一外部 HTTP 格式而要求所有业务改用某家提供方的字段，也不得把转换生成的对象当成提供方原始响应。

业务请求继续包含完整的共享 state、有唯一 ID 的题目、原始指令，以及 Choice 候选、Score 等级或 Noul 的真假条件。渠道转换只适配外部字段和表示方法：字符串保留原文；JSON 数据及结构化指令完整表达原有键、值和顺序；空描述仍表示未提供描述。不得摘要、截断、调用另一个模型改写，或增加业务条件。现有允许的 JSON 标量不能仅因渠道需要字符串而丢失；需要文本表示时必须保留该 JSON 值及类型的含义。Score 的空描述等级仍占据原索引。

| 业务含义 | OpenRouter Decisions | OpenAI Decisions | 返回给业务模块 |
|---|---|---|---|
| 共享输入 | `state` | `input` 中的完整文本表示 | 记录保留原始业务输入与实际发送内容 |
| 问题身份 | `questions` 映射的键 | `questions` 数组中的 `name` | 恢复原题目 ID 和原顺序 |
| Noul | `type: noul`，返回 `noul` | `type: predicate`，返回 `probability` | 条件成立的概率；真假条件不得反转 |
| Choice | `criteria` 映射与 `choice` | `choices` 数组与 `choice` | 原候选字符串 ID，以及实际返回的候选概率映射 |
| Score | 有序 `criteria`，返回 `score` | 有序 `levels`，返回 `score` | 原等级索引量表上的分数和概率；保留小数 |
| 概率分布 | 概率映射 | 带 `value / probability` 的数组 | 完整、无重复的原候选或等级概率映射 |
| 独立置信度 | 实际返回的 `confidence` | 实际返回的 `confidence` | 保留原值；缺失时保持缺失 |

Choice 的字符串 ID 不能与同文本的布尔值混同。Score 的概率按返回的等级索引关联，不按标签文本重新排序或改变范围。所选 API 允许省略的概率分布、legend、confidence、理由或用量缺失时保持缺失，业务继续使用原有可用性和阈值规则；不能补造。实际提供的概率分布须完整且无重复。所选 API 要求存在的字段缺失时明确失败。原始响应中实际存在的字段可在记录详情查看。

OpenAI 的 `refusal`、答案数量或身份不符、错误题型、未知候选、已提供分布中的重复或缺失概率项、无效数值均不能成为可采纳答案。任一题被拒绝或无效时，整次业务判断失败；保留实际响应及已知用量，不能将拒绝转换成 `unknown`、否、零概率或通过。

验收：两种 API 分别返回对应字段的同一固定答案时，业务模块收到相同的题目身份、Choice ID、Score 分数、Noul 概率和置信度。结构化输入、真假条件、空描述及索引可以从记录核对；拒绝及类型不符的回答不会触发业务行动。

**REQ-LUNA-003：完整处理 OpenRouter 的问题数限制。** OpenRouter 的 Luna 请求每次不超过 200 个问题。一次业务判断超过该数量时，完整覆盖所有题目，每题在本次尝试中请求一次，不静默只取前 200 题，不降低技能或日志候选的原配置上限。每个分批请求使用相同的完整共享输入、同一请求模型、同一渠道与同一组认证凭据。

所有题目有效返回后，按原 ID 和顺序向业务模块交付一次完整结果。任一分批失败、拒绝、无效、超时或取消，整次尝试均不能交付部分成功答案。多个请求共享本次尝试的原有总超时和取消范围；不会因为分批而为每批重新延长超时，也不引入自动重试或跨渠道回退。

这项外部接口限制只约束 OpenRouter 请求。官方 API 不宣称具有相同的 200 题硬上限；其请求若触发提供方的实际限制，遵循既有失败流程，不能偷偷删题。

验收：OpenRouter 的 200、201、401 题判断分别完整覆盖 200、201、401 题；任何请求均不超过 200 题，消费者只收到一个完整结果。第二批失败或总超时发生后，部分成功题目不被采用，后续未发送请求不再发出。

## MODIFIED Requirements

**REQ-LUNA-004：保存连接与凭据。**

之前：一个 profile 只有一套完整端点、模型、凭据引用与超时设置；凭据操作针对这一套连接。

现在：Jev、Luna / OpenRouter、Luna / OpenAI 各自保存端点与凭据引用；Luna 请求模型使用 REQ-LUNA-002 的渠道映射。Jev 继续读取已有 `baseUrl / model / credentialRef` 的实际值，不覆盖自定义值。共享 `timeoutMs`、`features` 与各功能的独立参数保留原值。保存模型、渠道及正在编辑的连接是同一份设置提交；拒绝或冲突的提交保留当前已保存设置与未保存草稿，不执行一半的切换。

新 Luna 连接默认使用彼此不同、属于本插件的凭据引用。用户可以显式配置其他合法引用；自动切换或页面加载不能复制、覆盖或保存密钥。密钥保存操作明确对应本次编辑的连接及已保存引用；若该连接或引用已改变，拒绝迟到的保存并提示刷新。一个渠道的迟到凭据状态或诊断响应不能覆盖另一个渠道的当前状态。未保存的连接不能被误当作已保存连接来存密钥或测试。

认证继续使用 DSH 凭据服务。设置读取仅返回存在、来源与可写状态，不返回密钥值；连接设置、连接身份、错误与新增网络记录不保存认证密钥或认证请求头。手动替换密钥成功后清空输入框。合法端点继续禁止 URL 内的用户名、密码、查询串与片段；同协议的合法自定义端点按所选协议处理，不自动改变模型或渠道。

验收：Jev → Luna / OpenRouter → Luna / OpenAI → Jev 后，每套连接可恢复，功能开关和参数不变。迟到的凭据写入不能改另一渠道或已变更的引用；配置和 Remote 查询看不到认证密钥。

**REQ-LUNA-005：尝试生命周期与故障处理。**

之前：每次尝试保存输入及连接信息，解析凭据并请求判断；`judge` 在服务失败后等待人工 Retry / Cancel，重试刷新输入；`judgeOnce` 只尝试一次。采纳前由业务模块检查原目标和上下文是否仍有效。

现在：每次尝试冻结所选模型、渠道、完整端点、请求模型、凭据引用、所解析的认证值和超时范围。进行中的尝试及其分批请求继续使用这份连接。用户保存的新选择供尚未开始的后续尝试使用；人工重试刷新业务输入，并使用重试时已经保存的连接。仅保存或切换设置不发起诊断、重试或业务模型请求。

认证失败、余额不足、限流、服务器错误、网络错误、缺少配置或凭据、无效响应及 provider 拒绝仍走原调用模式的失败处理。`judge` 等待显式 Retry / Cancel，`judgeOnce` 返回一次失败；既有业务旁路、人类审批、原文保留和采纳检查仍由原消费者决定。禁止故障后自动换到 Jev、另一 Luna 渠道或其他模型。超时、取消、关闭功能和服务释放继续阻止不应再派发的新请求；已发结果仍须通过原有有效性检查。

输入持久化失败时不请求模型；结果持久化失败时不把答案交付为可采纳成功。判断成功、业务采纳、原生授权和工具执行仍是不同事实，分别保留原记录和回执。

验收：请求途中从 OpenRouter 切到 OpenAI，原尝试的所有网络请求与记录仍属于 OpenRouter；下一次新尝试使用 OpenAI。原目标已改变时，完整有效答案也不能被采用。任一故障不触发另一模型或渠道的请求。

**REQ-LUNA-006：记录可复查并兼容历史数据。**

之前：辅助 ledger 保存每次尝试的业务输入、端点、配置模型、凭据引用、原始响应、规范化答案、时延、用量和行动回执。

现在：新记录还可辨认此次选择的模型及 API 渠道。每个实际网络请求的发送内容、题目范围、原始响应、提供方返回的模型和请求标识（若提供）、已知用量与结果均可关联回同一次业务尝试。详情区保留提供方原始响应，另展示业务实际收到的统一答案；不得用转换后的对象冒充原始响应。成功的统一答案必须能从该次实际协议的原始回答重新得到；重启后的持久读取也验证这一对应关系，不能只让实时调用通过而使官方原始回答的历史记录无法读取。

分批汇总仅累加实际已知用量；重复发送共享输入的用量不能隐藏。若某次请求的用量未知或尝试未完成，标明缺失或不完整，不能把缺失补零或宣称总量完整。实际返回的模型不能被页面当前选择或配置别名覆盖。旧记录缺少模型选择、渠道及网络元数据时仍可读，按原已存端点、模型和响应展示；不能凭元数据缺失一律认定其由 Jev 或某个渠道返回。

现有 profile 隔离、记录状态、行动回执的幂等与冲突处理保持原语义。历史输入、响应和回执不因切换渠道被重写或删除。

验收：分别查看三个连接产生的记录可区分真实连接；分批成功与失败均能核对实际请求和已知用量。升级前的成功、失败和中断记录继续可读，规范化答案与实际原始响应一致。官方响应保留其数组格式，重启后仍得到原规范化答案；若原始概率被修改而已保存答案未同步，该记录不能通过一致性验证。

**REQ-LUNA-007：阶段导航使用实际判断连接。**

之前：已结束的完整 step 在用户手动分析后分类；每个待分析 step 派发前重建输入。分类复用取决于材料、规则和连接信息；不符合当前指纹的结果显示过期。

现在：同一套行为使用当前所选的 Jev 或 Luna 连接。准备输入、凭据脱敏、派发判断及保存结果对应同一次尝试的实际连接；发生异步设置变化时，不能把旧连接准备的输入或结果冒充新连接的结果。每个后续 step 派发前按已保存连接重新准备输入，因此无需新增切换即停止整个阶段批次的规则。

所有已配置判断连接的已知凭据值纳入历史输入的脱敏；必要的凭据读取失败时不发送未确认安全的历史材料。凭据值不进入分类指纹或公开连接身份。目标 step 完整性、既有输入预算、媒体处理、取消及认证故障停止派发规则保持原行为。

升级本身不能使输入、规则及实际连接均未变化的既有 Jev 结果失效。切换到不同实际连接时，旧结果按指纹显示过期并保留；切回原连接后仍按原材料与连接规则判断能否复用。打开、切换、搜索和查看历史不自动分析；用户显式重分析才建立新尝试。拒绝或失败不变成 `unknown` 阶段。

验收：已有 Jev 分类在无连接变化的升级后可复用；选择 Luna 后该 Jev 结果显示过期。分析途中换渠道，已发结果关联原连接，后续 step 按新连接准备；当前指纹不匹配的答案不能成为当前有效分类。

**REQ-LUNA-008：诊断所选连接。**

之前：“测试连接”仅发送一个固定 Noul 诊断，并记录结果；配置了密钥不等于连通性成功。

现在：“测试连接”使用点击时的已保存模型和渠道，发送不含用户任务内容的固定 Choice、Score、Noul 诊断。成功表示三类答案均通过对应协议转换和完整性校验；失败显示安全的原因并保留记录。调用产生一条诊断操作，不启用业务功能、不运行主 Agent 或工具、不更改连接。诊断结果明确对应当时的连接，不被迟到响应错配为另一个连接成功。

验收：OpenAI 官方诊断包含对应的 predicate；OpenRouter 诊断包含 noul。任一题拒绝、类型不符或不完整时不能报告连接测试成功；点击前后的普通设置读写均不产生模型请求。

**REQ-LUNA-009：安装后的完整用户行为。**

之前：安装包同时提供 Host 判断服务和 Client 设置、记录及阶段导航；GitHub 安装入口读取仓库已提交的 runtime 构建结果。

现在：支持的 DSH profile 从实际安装入口加载后，即可保存三套连接、选择模型与 Luna 渠道、管理对应凭据、进行诊断及查看记录。Host、Client、Remote 和实际安装产物对本规格的理解一致。使用现有设置与本地化组件，中英文页面提供相同功能，并明确区分判断服务与主模型。显示某次模型身份时使用该次实际记录，不将所有 Luna 结果仍标成 Jev 模型判断。

原包名、公共业务入口、功能标识和既有 Session 事件含义保持可用；渠道差异由共用判断服务承担。受影响的用户说明与公共 API 文档同步到实际交付行为。判断对主模型产生的可见影响继续由既有 Session 记录重建；辅助判断仍记录在插件 ledger。

验收：通过实际安装的 Host 与 Client，完成两个 Luna 渠道及 Jev 的选择、诊断和记录读取；既有业务功能仍通过原有公开扩展点触发和采纳，不依赖修改 DSH、Mu 或 Cua。

## REMOVED Requirements

无。Jev、已有连接配置、功能开关、业务判断题、Session 事件和历史记录均保留。没有移除主模型提供方或权限机制。

## 保持不变的行为

所有功能继续独立启用，新功能注册默认关闭；切换判断模型或 Luna 渠道不改变功能开关或开启其他模块。现有用户设置值全部保留；未设置时仍采用原功能默认值。技能默认展示 5 项，glob 默认最多 40 个候选参与判断、展示 12 个排序路径，超过候选上限仍整体旁路。跑偏检查默认每 6 步，目标连续 3 轮无进展仍按原规则处理。日志默认省略阈值 0.8、等待预算 4,000 ms；历史阶段默认前序 2 步、每步 700 字符、请求预算 48,000 字符、并发 1。其他配置含义和范围沿用现有实现。

主模型继续决定回复、工具调用、技能加载和执行。判断仅提供原有有限选择、排序、提醒或审批代答，不新增规划器、生成式解释、主动执行、强制指令阻断或跨模型级联。原生审批与 sandbox 仍决定实际授权；有效判断不等于工具成功。

历史分类的最小单元仍是一个完整 DSH step；阶段标签、概率、置信度、原生工具错误及轮次结束事实仍分别展示。概率和 confidence 不因更换模型重新标定；缺少概率或置信度时，业务仍按原有规则决定保留、未确定或回退。

## 输入、默认值、顺序与优先级

| 项目 | 规则 |
|---|---|
| 缺少新选择字段 | 默认 Jev，读取原完整端点、原模型与原凭据引用 |
| 首次选择 Luna | 默认 OpenRouter；未配置另一渠道不能自动代用 |
| Luna / OpenRouter 默认端点和请求模型 | `https://openrouter.ai/api/alpha/decisions`；`openai/gpt-6-luna-decisions` |
| Luna / OpenAI 默认端点和请求模型 | `https://api.openai.com/v1/decisions`；`gpt-6-luna` |
| Luna 默认凭据引用 | OpenRouter 为 `JEV_LUNA_OPENROUTER_API_KEY`，OpenAI 为 `JEV_LUNA_OPENAI_API_KEY`；Jev 原引用不变 |
| 共享超时 | 保留原已保存值；未配置仍为 10,000 ms，范围仍为 1 至 300,000 ms |
| 空端点 | 保留尚未配置时可打开设置页的能力；请求时明确报告缺少连接 |
| Luna 模型标识 | 按所选 API 使用表中固定 Luna 标识；其他 GPT 模型不属于本次模型选项 |
| 自定义地址 | 必须符合现有端点校验；仍使用显式选择的 API 协议与相应 Luna 模型 |
| 配置冲突 | 已保存且成功提交的配置生效；拒绝的草稿不改变运行中设置 |
| 进行中与后续尝试 | 已开始的尝试使用其冻结连接；后续新尝试使用当时已保存的选择 |
| 题目与答案顺序 | 全部题目按原 ID 关联；向消费者交付原题目顺序，不能按响应数组或概率排序重新关联 |
| 业务排序 | 继续由原业务按返回概率与原候选顺序排序；渠道转换不另作排名 |

空字符串、null、对象或数组的含义按原业务输入保持；不可发送给某协议的表示必须完整转换或明确失败，不能静默跳过字段。缺少凭据不改变所选连接。用户输入和 Host 授权仍由原来源规则决定，提供方响应不能成为新的用户授权。

## 失败与回退

| 条件 | 可观察结果 |
|---|---|
| 连接未配置、凭据缺失或凭据读取失败 | 对应连接失败；不调用另一连接 |
| 设置保存冲突或拒绝 | 当前选择不变，保留草稿并提示；不发模型请求 |
| 凭据保存对应的连接已改变 | 拒绝旧保存；不写入新引用或新渠道 |
| HTTP 401 / 403、402、429、服务器或网络错误 | 安全原因及实际尝试可查；按原调用模式等待人类重试/取消或返回一次失败 |
| HTTP 成功但含 refusal、错误题型、未知候选或不完整答案 | 整次判断失败；保留响应及已知用量，不交付可采纳部分结果 |
| OpenRouter 任一分批失败或超时 | 已知网络请求仍可查；后续未发送请求停止；消费者无部分成功答案 |
| 超时、用户取消、目标失效或服务释放 | 保留原取消及不采纳行为，停止不应再派发的请求 |
| 输入或结果记录写入失败 | 输入未存则不请求；结果未存则不报告可采纳成功 |
| 阶段输入安全性或当前指纹无法确认 | 不发送未确认安全的材料；原成功历史保留，当前分类不冒充有效 |

禁止自动跨模型、跨 Luna 渠道或转向普通生成 API 回退。没有新增自动重试。原业务已有的旁路、原文保留、未确定处理及人工审批仍按该业务已有条件发生；不能把服务失败当成业务通过。

## 端到端传递

设置入口将模型、Luna 渠道和对应连接保存到当前 profile。凭据值交由 Host 凭据服务保存；设置状态读取只取得非秘密信息。新判断尝试取得已保存的选择，并将其身份与完整业务输入关联到辅助记录。

共用判断服务依据已选择 API 转换完整请求。OpenRouter 请求遵守其每次问题数限制，官方请求遵守官方 Decisions 字段；两者都只调用所选 Luna 能力。原始网络响应与实际用量关联本次尝试，完整有效的答案转换回原业务类型。

原业务决定是否采纳和执行，并继续写入相应 Session 影响及行动回执。Client 读取对应记录展示该次真实连接、原始回答和业务结果。阶段导航通过材料、规则与实际连接判断缓存是否当前，既有结果与原 Session 始终可独立查看。

## 对外契约

用户可观察的新增能力是 profile 内模型二选一，以及 Luna 的两种 API 渠道。已有 `@dsh-jev/plugin` 安装入口、共用业务判断入口、有限答案含义、功能标识、主模型配置和原生授权语义继续可用。

已有 `baseUrl / model / credentialRef / timeoutMs / features` 配置继续可读取。新增设置按模型及渠道保存，公开配置文档说明对应默认端点、固定 Luna 模型和凭据引用。具体内部字段组织由实施决定，不要求迁移或覆盖旧字段值。

旧辅助记录允许缺少新渠道信息；新记录足以核对真实 API 数据及规范化答案。所有持久读取需支持原有效记录，不能依赖把旧响应改写为新 API 格式。改变辅助格式不改变 DSH 已发布 Session 数据，也不声明旧插件版本可读取新记录。

记录、诊断和页面展示应区分“已配置”“协议判断成功”“业务已采纳”“原生授权”“工具成功”，不能互相替代。官方和 OpenRouter 相同业务答案的映射一致，不保证两种实际请求得到相同概率、置信度或最终判定。

## 非目标

不替换主 Agent 模型、工具执行或 sandbox；不改变已有判断题、业务阈值、候选发现、执行权限或功能覆盖范围。不恢复暂停的网页或 Computer Use 方向，不修改 DSH、Mu 或 Cua 产品代码。

不新增自动级联、自动跨渠道回退、按功能独立模型、shadow 模式、任意 GPT 模型选择、聊天 API 模拟概率或自动后台分析。不因 Luna 的媒体能力扩大现有判断输入到图片、音频或其他未启用媒体。

不迁移、覆写或删除历史Session和辅助记录，不改日常用户profile，不保存密钥到规划文件或公开材料。不以协议兼容或固定样例宣称自然任务收益、准确率提升或实际费用。不自动生成或合并累计Full Spec，不删除其他分支或清理实验工作区；发布仅限本功能代码、说明及相关官网内容。

## 决策闭合

**已确认方向：** 用户要求 Jev / Luna Decisions 二选一、其他业务机制保持现有行为；补充要求 Luna 同时兼容 OpenRouter 与 OpenAI 官方 API，保留同一指定模型能力。用户已确认接口转换底座，并通过本规格要求执行，实质问题需沟通。
