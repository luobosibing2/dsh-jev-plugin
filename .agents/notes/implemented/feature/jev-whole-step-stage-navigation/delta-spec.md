# Jev 完整 step 阶段导航增量规格

状态：已实现并合并，Jev 仓库 PR [#3](https://github.com/luobosibing2/dsh-jev-plugin/pull/3) 已进入 `main@d6af739`。用户确认完整 step 逻辑、现有 Jev 插件独立功能、手动分析与持久复用，并授权实施和合并。理由与结果见[已实现决策](decision.md)。

## 目标与范围

在 DSH 会话的独立“阶段导航”标签页中，把完整 step 的 Jev 分类组织成可定位原文的轮内阶段，让用户阅读一轮内的工作推进过程，并在多个轮次之间切换。

本次范围是当前选中会话的历史阅读与辅助分类，包含六阶段判断、原文导航、输入输出记录、失败与取消状态。默认不递归分析关联子会话，不控制 Agent 执行，不改写原生会话内容。本轮实施并完成必要本地验证，构建可安装验收包。

落点是现有 Jev 插件的独立功能，通过 DSH 的会话视图扩展提供新标签页，复用宿主历史读取和 Jev 公共判断能力。本规格不授权修改 DSH 产品代码。

## ADDED Requirements

- **REQ-STAGE-01 — 完整 step 是唯一最小分类单元。** 一个分类单元对应一个有稳定身份的 DSH 逻辑 step，整体包含该步最终已记录的 reasoning、对外文本、全部 ToolCall 及配对工具结果。多个 ToolCall、reasoning 自然段、工具输出行、同 step 内模型重试都不得单独成为分类单元。无工具的最终回复仍可分类。失败与中止保持原始状态；没有可分类材料的 step 显示未分析原因，不凭空生成阶段。
  - 验收：一个 step 含 17 段 reasoning、一段文本和两个工具调用时，只生成一个分类目标与一个阶段结果；重试记录不增加目标数。

- **REQ-STAGE-02 — 类型化阶段分类。** Jev 从以下八个候选中为完整 step 选择一个：`input_parsing`、`problem_understanding`、`solution_planning`、`implementation`、`review_validation`、`delivery_finalization`、`mixed`、`unknown`。它判断该 step 当前主要工作目的，不按工具名、文件名或 Think 中的单句措辞切换类别。输入解析指初始识别任务输入与约束；问题理解包括建立事实、查根因和解决未决问题；方案规划指依据明确要求选择或修订方案；实现与调试包括落实修改及其局部读取、测试、返工；审查验证指以判断已有产物是否合格为主要目的；交付收尾包括按已知实现整理证据、同步文档与交付。多个不可归一的主要目的允许 mixed，证据不足允许 unknown。
  - 验收：相同的 read 或 test 操作在不同任务目的下允许不同标签；一个 Think 中写“Plan”不自动产生规划阶段；返回不在候选集合内的值不可作为有效分类展示。

- **REQ-STAGE-03 — 完整目标输入与明确上下文。** 分类输入包含当前 step 前已经生效的用户请求及补充、有限的前序 step 上下文和当前完整 step；不得把后续 step 或最终结果放入输入以倒推当前目的。当前 step 的 reasoning、正文、工具参数和结果不得为了满足预算而静默截断。前序上下文可按公开配置做摘录，必须记录范围和截断标志。原始记录不包含的 reasoning 不补造。图片等非文本材料只保留存在标记和可用元数据，明确其未被 Jev 理解。
  - 验收：长 Think 超过前序摘要上限时仍完整保留；超出配置或服务可接收规模时明确跳过，不把截断片段冒充完整 step；请求记录可还原实际发送内容。

- **REQ-STAGE-04 — 轮内连续阶段。** 程序按 DSH turn / step 顺序展示结果，只合并同一轮中相邻、均有有效结果且类别相同的 step。跨轮、缺步、未分析、失败、取消或过期结果必须断开合并。相同阶段在后续再次出现时形成独立连续段。阶段段的身份不依赖会变化的可见行号。六阶段不强制出现，不填充缺失类别，不由程序平滑或改写 Jev 标签。
  - 验收：标签序列 implementation × 11、review_validation、implementation × 2 形成三段；第 13 步的实现段与第 1 步的实现段独立可选。

- **REQ-STAGE-05 — 独立标签页与多轮导航。** 仅在本功能开启时，在“轨迹”后提供“阶段导航”标签。左侧按轮次列出用户请求或其可识别摘录、原生步骤统计、分析状态和连续阶段；右侧保留选中轮次的原文，点击阶段定位并突出相应完整 step。Think、全部工具调用和返回可展开；不重排或改写原始记录。相同阶段在不同轮次中分别定位。搜索只筛选右侧原文，不删除左侧轮次目录；切轮后更新请求、原文和选中状态。导航与长原文各自可滚动，窄屏可收起导航。
  - 验收：查看第二轮的实现段时，第一轮目录仍可访问；原生“轨迹”标签不出现本功能的阶段导航；补入更早历史后，已有选中 step 的身份保持稳定。

- **REQ-STAGE-06 — 分析入口与范围。** 第一版只由用户在标签页点击发起：可分析选中已结束轮，或分析本会话所有已结束轮中的未分析 step。正常结束、失败和用户中止的轮均可选择；进行中的轮暂不启动分类。发起时展示待处理 step 数与材料范围，并固定本次读取范围。打开页面、切轮、展开 Think、搜索和读取缓存均不调用模型。历史尚未载入时先获取所选范围，不能把当前可见窗口冒充完整轮次。
  - 验收：打开有 18 轮历史的页面而未点击分析时，Jev 请求数为零；选中第 8 轮时仅分析其 14 个 step；结束状态为用户中止不导致该轮从选择器消失。

- **REQ-STAGE-07 — 结果保存与复用。** 持久保存原始回答、解析后的标签、源 step 关联、实际分类输入、分类规则版本和所用模型配置。相同材料与规则、相同模型连接配置下，重新打开或重复发起未分析范围时复用已有有效结果；重复点击不产生同目标并发副本。输入、脱敏规则、分类候选或模型配置变化后，旧结果显示为过期，不能混入当前连续阶段，也不能静默重跑。用户可主动重新分析；新尝试完成前保留既有记录的可查看性。
  - 验收：完成一轮分类后重启应用，再查看同一轮不增加模型请求；改变分类规则后旧记录可查但标为过期，只有显式重分析才产生新请求。

- **REQ-STAGE-08 — 真实结果与来源可核对。** 每个 step 显示实际 Jev 标签、返回的 confidence / probabilities（如果存在）、所用模型与调用状态，并可查看实际发送的脱敏输入、原始回答和对应原文位置。原生请求编号是辅助展示，不能代替稳定 step 身份。confidence 未校准，不作为正确率；未返回的信号显示未提供，不编数值。低 confidence 不自动改类、抹除或重跑。页面不生成自由文本分类理由，也不把任取的几条记录称为 Jev 选出的决定性证据。
  - 验收：原始响应为 implementation、confidence 0.45 时仍显示该标签与原值；用户能核对其实际输入及返回；UI 中不存在手写或合成的生产分类。

- **REQ-STAGE-09 — 分析状态与执行状态分离。** 分类成功只表示得到合法阶段结果；工具的 isError、缺失结果、原生轮结束原因和是否有最终回复独立显示。中止、失败、未分析和 unknown 分别表达，不能互相替代。未完成的 step 不假装已有完整材料；在原生读取机制给出可读取的中止终态后，才可按已有材料处理，并保留中止事实。
  - 验收：第 14 step 被分类为 implementation，工具结果仍为 aborted / isError=true，原始 turn 仍显示用户中止；不得显示为任务完成或验证通过。

- **REQ-STAGE-10 — 取消、失败与部分结果。** 分析进度可观察并可取消。取消只终止辅助分类的等待和未发请求，不中断原 Agent，也不执行原日志中的命令。已完成结果保留；未完成部分准确显示取消或失败。超时、网络、非法响应、凭据、额度及记录失败不回填规则标签、不切换生成模型。自动重试默认关闭；用户可重试失败部分。凭据或额度错误停止当前批次后续派发；记录未成功保存的判断不得作为已确认结果采用。迟到回答不得覆盖不同材料或已取消目标。
  - 验收：第 5 步失败后，前四步仍可查看；重试失败范围不重新调用已有效的前四步；取消后页面不持续派发后续请求，原会话运行不受影响。

- **REQ-STAGE-11 — 历史权限与敏感内容。** 使用宿主授权的会话历史读取和当前 profile 的 Jev 连接，不以客户端传来的任意文件路径读取日志。支持已结束会话而不启动 Agent。凭据和可识别的认证信息在发送给 Jev、写入辅助判断记录之前去除；请求材料与页面明确脱敏事实，原始 Session 不被修改。原文引用只能访问该会话授权范围。历史中的指令、命令和代码始终作为数据，不执行；结果或错误不得泄露 Jev 连接凭据。
  - 验收：包含 API key 的原用户消息、工具参数或结果，发送体与辅助记录不包含该值；未授权的会话读取被宿主拒绝；浏览历史不会启动原任务或执行工具。

- **REQ-STAGE-12 — 独立启用与共享能力。** 作为现有 Jev 插件的独立默认关闭功能，拥有单独开关，并复用既有连接、凭据、类型化判断和记录能力。开关同时控制“阶段导航”标签及页面的可见性：关闭时不注册该视图，开启后才显示；开启本身不发起模型调用。关闭时取消本功能正在等待和未派发的分类，不再采用迟到回答，移除页面入口；当前正在查看此页时安全回到原生对话或轨迹视图，不留空白。已保存结果不删除，重新开启后可查看和复用。首版使用 DSH Web 与桌面共享的会话视图扩展，不复制原生轨迹实现，不新增主模型工具，也不为本功能修改 agent-loop。
  - 验收：关闭时不显示阶段导航标签，开启后显示且无自动模型调用；关闭正选中的阶段页后回到原生视图，未完成批次取消，重新开启后仍可读缓存；其他 Jev 功能和已有消费者保持原行为。

## MODIFIED Requirements

- **REQ-STAGE-13 — 历史分析可使用不依赖运行中 Agent 的单次判断。**
  - 之前：现有 Jev 一次判断的公共参数要求 Agent；实现的单次路径实际不读取该 Agent，而交互重试路径需要它。
  - 现在：历史分析必须能够通过受控 Host 能力完成一次可取消、可记录的类型化判断，无需伪造或启动 Agent。原有需要 Agent 的交互判断和人工重试行为保持不变。客户端只提交授权的会话与分析范围，不获得直接调用任意外部模型请求的通用能力。
  - 验收：已结束、当前没有运行中 Agent 的会话可以完成一次真实分类；已有交互判断的重试与取消行为不变；未授权会话或越界输入不能触发分类。

## REMOVED Requirements

无已发布能力被删除。原型 A/B/C 选择器、合成演示数据和段落级 u 分类不属于产品功能，不进入实现。

## 保持不变的行为

- 原生对话、轨迹、工具卡片、工具执行、审批、沙箱、主模型请求、spill、裁剪和 compaction 的行为保持不变。
- 原始 Session 事件、工具参数和结果不被分类器修改；阶段分析不注入主模型上下文，也不转成用户消息或助手消息。
- 分类结果属于辅助分析记录，不代表新工具执行、主模型 token 消耗或任务验收结果。
- 主代理与子代理仍由 DSH 的真实会话关系区分，不按目录、文本或时间相近猜归属；首版不自动遍历子会话。

## 输入、默认值、顺序与优先级

以 DSH 的逻辑 turn / step 及持久事件作为身份和顺序依据。每个 step 的最终已记录 assistant 输出与工具结果整体归类；重试属于原 step，保留重试事实和可用输出，不重复展开已嵌入最终消息的 stream。尚未闭合的 step 显示进行中，不能被当作已完成样本。

分类上下文只使用目标 step 当时已经生效的请求与前序材料。初始前序摘录采用实测口径：最多两个前序 step，优先原对外文本、工具名和错误状态；缺少对外文本时才取 reasoning 摘录，每步最多 700 字符并显式标记截断。数量和字符上限是可配置默认，不影响目标完整 step 的保留。

默认保留八个候选及固定中文名称，按当前完整 step 的主要目的判断，不把完整轮次的宏观标签复制给所有 step。前序标签不是本次输入。所有回答先验证候选合法性，再展示原值；mixed / unknown 不用规则回填。

采用手动分析、持久复用和现有 Jev 插件内新增功能。默认关闭、无自动重试；超时与连接继续服从 Jev 已有配置，批次先采用单并发，允许通过受验证配置调整。

当前完整 step 超出配置或服务容量时不裁成更小分类单元，也不静默删减 Think 或工具结果；显示材料过大并保留原文。二进制附件不发送给文本分类器，显示未分析该模态。无材料与模型返回 unknown 分别记录。

保存复用时，材料、脱敏规则、分类规则、候选和 endpoint / 模型配置参与有效性判断。凭据值不进入指纹。模型别名可能在服务端改变；仅使用别名时不能声称自动识别远端更新，显示实际返回模型并允许显式重分析，不通过隐式探测请求制造额外调用。

## 失败与回退

失败不改变原会话，原文和有效历史结果继续可读。缺少历史、配对结果或权限时先显示材料状态，不把当前窗口自动视为全量。缺少部分证据不伪造结果；只有实际获得合法分类才显示模型标签。

认证或额度错误终止本次批次后续派发并显示可操作的配置问题；其他单步失败记录范围，用户可仅重试失败部分。取消和插件卸载终止所属辅助请求；已取消或输入已变化的迟到结果不作为当前结果。服务或记录失败不降级为自由生成模型、关键词分类或旧段落分类。

页面、应用重启后保留已完成记录；未完成请求显示中断，不假装完成，也不自动续费重跑。删除缓存和记录保留期不在本次新增管理功能范围，遵循现有宿主存储管理能力。

## 端到端传递

用户在独立标签页选定轮次和分析范围 → Host 通过宿主权限与历史读取能力获得一致的持久事件范围 → 根据 DSH 逻辑 step 装配完整目标及前序上下文并脱敏 → Jev 公共单次判断服务记录实际输入并执行 Choice → 校验回答、取消状态和来源有效性 → 保存可核对的辅助结果 → 按轮内相邻同标签合并 → 多轮导航定位回完整 step 原文。

阶段与原文通过稳定的会话、turn、step 和事件关联，不依赖可见序号、当前分页或时间近似。原生历史分页和生命周期状态保持权威；辅助读取不激活 Agent。GUI 交互入口使用宿主认证和授权能力，自定义 HTTP 路由不能因挂在 WebServer 上就被视为已认证。

## 对外契约

用户可见新增“阶段导航”标签、轮次与阶段目录、完整 step 原文、分类信号、分析进度、取消与失败重试入口。原生“对话”和“轨迹”保持独立；不新增 CLI 或主模型工具。

辅助记录必须能恢复所选材料、实际发送体、模型回答、采用状态与来源范围。持久化采用现有 Jev / 宿主辅助存储约定，不向原 Session 注入分析消息。结果数据不以纯 UI 状态冒充业务记录。

Jev 公共单次判断能力须支持无运行中 Agent 的历史消费者，并更新其实际消费者；本规格不冻结内部函数签名或文件拆分。UI 文案使用宿主 locale 机制，Web 和桌面按同一标签和交互语义呈现。

## 验收示例

| 场景 | 给定 | 当 | 则 | 覆盖需求 |
|---|---|---|---|---|
| 完整 Think 与多工具 | 一个 step 有 17 段 reasoning、正文、两个 ToolCall 与结果 | 分析该 step | 只有一个分类目标与标签，材料完整可查 | REQ-STAGE-01, REQ-STAGE-03 |
| 无工具最终回复 | 已结束 step 只有最终回复 | 分析 | 仍作为一个完整单元，不因无 ToolCall 被丢弃 | REQ-STAGE-01, REQ-STAGE-02 |
| 同 step 重试 | 同一 turn / step 有失败 attempt 和最终消息 | 装配 | 不重复计算 step，重试事实可查 | REQ-STAGE-01 |
| 六阶段不齐全 | 整轮只有实现和验证目的 | 分类 | 不制造其他阶段来补齐六种 | REQ-STAGE-02, REQ-STAGE-04 |
| 三段序列 | 受控合法结果为 I×11、V、I×2 | 展示第 8 轮 | 得到 1–11、12、13–14 三段，两个实现段独立 | REQ-STAGE-04, REQ-STAGE-05 |
| 相同标签跨轮 | 两轮结尾与开头均为 implementation | 展示 | 不跨轮合并 | REQ-STAGE-04, REQ-STAGE-05 |
| 中间缺步 | step 1、3 同类，2 未分析或失败 | 展示 | 两段分开，缺步状态可见 | REQ-STAGE-04, REQ-STAGE-10 |
| 进行中 step | Think 或工具仍未结束 | 展示当前会话 | 显示进行中，不伪装完整目标发起分类 | REQ-STAGE-01, REQ-STAGE-06, REQ-STAGE-09 |
| 中止轮的历史分析 | turn 由用户中止且有已记录 step | 用户选择该轮 | 可以读取并分析材料，保留中止状态 | REQ-STAGE-06, REQ-STAGE-09 |
| 分类不等于执行成功 | step 标签 implementation，工具 isError=true、aborted | 展示 | 同时显示分类与工具失败，不宣称完成 | REQ-STAGE-08, REQ-STAGE-09 |
| 模糊测试目的 | 受控返回 impl 0.52 / review 0.48 与 review 0.64 / impl 0.36 | 展示两个 step | 保留各自实际标签、分布和 confidence，不自动平滑 | REQ-STAGE-02, REQ-STAGE-08 |
| 仅打开页面 | 未分类的历史会话 | 进入页、切轮、展开原文 | 无 Jev 调用 | REQ-STAGE-06 |
| 按轮分析 | 会话 18 轮，选中已结束第 8 轮的 14 步 | 点击分析本轮 | 仅处理这 14 步，展示进度；不分析其他轮 | REQ-STAGE-06 |
| 重启复用 | 同材料、规则和模型配置已有有效结果 | 重启后查看或补齐未分析部分 | 不重复调用有效目标 | REQ-STAGE-07 |
| 材料或规则改变 | 原结果已保存 | 输入或分类规则发生变化 | 标记过期，不并入当前阶段，不自动重跑 | REQ-STAGE-07 |
| 取消与重试 | 部分已完成、部分在运行或排队 | 取消后重试未完成部分 | 已完成结果保留；取消后停止新派发；只重试所选失败范围 | REQ-STAGE-10 |
| 非法模型回答 | 回答缺失或选择未定义类别 | 接收结果 | 显示判断失败，原文保留，不产生标签 | REQ-STAGE-02, REQ-STAGE-10 |
| 材料过大或分页未齐 | 完整目标超限或历史未完整读取 | 发起分析 | 明确显示原因，不静默截断、拆段或按可见窗口冒充全轮 | REQ-STAGE-03, REQ-STAGE-06 |
| 凭据混入历史 | 用户或工具内容含认证值 | 准备请求、记录和展示 | 分类输入与辅助记录均脱敏，原 Session 不变 | REQ-STAGE-11 |
| 已结束会话无 Agent | 宿主可授权读取但没有运行中 Agent | 手动分类 | 可通过单次辅助判断完成，不启动原任务 | REQ-STAGE-11, REQ-STAGE-13 |
| 多轮与原文定位 | 两轮存在同名阶段且历史继续分页 | 切轮、选段、搜索 | 定位准确，目录保持；搜索仅影响右侧原文 | REQ-STAGE-04, REQ-STAGE-05 |
| 功能开关与可见性 | 本功能默认关闭，其他 Jev 功能开启 | 开启，再在分析中关闭并重新开启 | 关闭时标签隐藏，开启才显示且不自动调用；关闭取消分析并返回原生视图；重开可复用缓存，其他功能不受影响 | REQ-STAGE-05, REQ-STAGE-07, REQ-STAGE-10, REQ-STAGE-12 |

验收采用固定响应检查装配、合并和展示；真实模型样本用于评估语义边界，不能把一次实测标签固定成普遍正确答案。首次验收至少覆盖带多工具的完整 step、无工具最终回复、实现内测试、以验收为目的的测试、中止结果、未载入历史、失败与取消，并保留实际模型输入输出。用户在实际 profile 中验收是插件交付的一部分；当前实验不代替该验收。

## 非目标

- 不做 reasoning 自然段分类，不恢复旧 u 分段实验，不要求每轮出现全部六阶段。
- 不生成阶段标题、分类解释、总结文章或“决定性证据”叙述；原文定位不是模型证据选择。
- 不新增偏离监控、完成监督、自动续跑、任务评分或行动干预，不重复现有 Jev 监督功能。
- 不推断内部认知耗时，不新增阶段耗时、token 或费用分摊，不把并行子代理耗时相加为墙钟时间。
- 不遍历全机器日志或全部工作区，不自动递归分析子会话，不支持任意本地路径导入。
- 不将原型直接作为生产实现，不迁移既有 Session 数据；本次未安装到用户日常 profile，也未发布 npm 包。

## 决策闭合

**已确认的用户决定：**完整 step 为最小单元；一轮由多个 step 组成；Jev 每步分类、轮内连续同类合并；独立插件标签位于轨迹之后；采用 C 布局并考虑多轮；先使用真实轨迹与 Jev 验证，页面不得臆造分析结果；功能并入现有 Jev 插件，以独立默认关闭开关控制启用与标签页可见性，关闭取消辅助分类并保留缓存；手动按已结束轮触发；持久保存与复用；本轮实施并本地验证。

**实施前核对的代码事实（基线）：**DSH 的 [conversation.view 注册](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/ui-trajectory/src/client/index.ts)（67–112 行）支持独立视图；[历史读取](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/api/session-controller/src/history.ts)（71 行起）可读取分页历史而不激活 Agent。现有 [Jev 单次判断](https://github.com/luobosibing2/dsh-jev-plugin/blob/cd041b90a3a291d832d75030ea92975501280f63/packages/jev/src/index.ts)（41–50、217–253 行）公共参数要求 Agent，但该单次实现不读取 Agent；[类型化协议](https://github.com/luobosibing2/dsh-jev-plugin/blob/cd041b90a3a291d832d75030ea92975501280f63/packages/jev/src/types.ts)（6–17 行）与 [wire 校验](https://github.com/luobosibing2/dsh-jev-plugin/blob/cd041b90a3a291d832d75030ea92975501280f63/packages/jev/src/wire.ts)（64–118 行）支持有限 Choice 回答。原生轨迹没有本功能所需的通用行注解接口，本方案使用独立标签而不改造其内部布局。

**实测事实：**完整 step 报告（原始本地材料未公开）及原始结果（原始本地材料未公开）记录 14 个完整 step、14 次成功请求、服务模型 jev-1.13.0、无重试，结果为实现 1–11 → 验证 12 → 实现 13–14。第 9、12 步 confidence 分别 0.45、0.57，分类边界未校准。原始轮由用户中止。实验是直接 API 调用，未验证插件 Host、权限、取消、缓存或实际 profile GUI 集成，也未给出准确率。实测材料是本地证据，不随插件分发。
