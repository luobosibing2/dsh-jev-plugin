# REQ-JEV-LOG 增量规格：日志省略受控案例实验

Status: proposed。用户已授权继续真实日志省略实验；本规格拥有本轮固定输入、对照与证据要求，理由见[Decision](decision.md)。

## 目标与范围

验证现有output-admission和test-log-admission在发布版DSH原生bash结果中的判断、省略/保留、重要信息保护及原文恢复。采用6个人工固定日志案例、每例baseline/开启两日志功能各一次，不测通用修题收益、不改变产品代码。Sol负责准备和核验，主代理唯一执行收费调用。

## ADDED Requirements

- **REQ-JEV-LOG-01 固定身份与隔离**：首次收费前冻结6例日志、emitter、退出码、原生任务、真值、全部运行/分析脚本、插件tar/组件版本/镜像/Node/npm锁、模型配置、价格和顺序。每例两个独立Docker trial同输入，Agent120秒、并发1、无自动重试，verifier关闭；无web工具或隐藏答案。baseline12功能关闭，开启组只开两日志功能，selection和stage关闭，工具schema相同。DSH danger-full-access仅用于已授权的默认Docker真实任务，不放宽Docker权限。
- **REQ-JEV-LOG-02 六类覆盖**：短general不足6000旁路；长general可匹配的进度及重复warning；被识别的普通PASS测试协议；带失败、420ms慢项、显式具名快项和exit1的测试协议；足够长的byte-identical重复失败详情及普通PASS；同长general但明确要求完整证据的旁路。日志是合成协议输出，不宣称真实软件build/test通过。默认general6000/test4000、block1200、max48/24、wait4000ms、概率0.8、净省300+10%不改变。候选及保护覆盖在收费前由源规则及发布版原生mock核定，可为有效覆盖调整人工输入；收费后不据结果改输入、阈值或重跑。
- **REQ-JEV-LOG-03 原生状态与保护**：emitter通过真实原生bash前台输出固定bytes及0/1退出码。普通bash非零退出与工具isError分别记录，不伪装为同一字段；基础设施错误按产品旁路，已识别失败测试按专用分支处理。保护首尾、失败原始详情、摘要、任务具名项、>=300ms慢项、状态及恢复标记。若删除这些要求的证据，判保护失败并停止追加，不修饰为收益。
- **REQ-JEV-LOG-04 实际判断与采用**：账本逐次保留request候选、choice/概率、attempt状态、真实response model、usage/延迟及最终receipt。仅choice omit且prob>=0.8可计Jev选择；重复失败规则替换独立计数。Jev成功但保留全部或净省不足是有效负结果，不强制省略。失败/超时按产品原文回退，保留实际异常与用量未知并暂停后续试次，不改变默认4秒等待。
- **REQ-JEV-LOG-05 分层恢复证据**：分别记录hook完整原文、规则/Jev候选及原始行范围、提案文本、最终model-visible文本、结构化value/exit/isError和DSH原生spill/压缩事实。采用省略前保存的恢复原文须与完整hook输入逐字/哈希一致，恢复引用须可由原生read取回；模型实际read与仅存在文件分开。提示不以full/complete/raw/verbatim等意外触发全文旁路，只有显式保留案例要求完整证据。实际助手可见前言若触发全文或anchor保护，按观测分类，不隐藏或重跑。
- **REQ-JEV-LOG-06 用量与报告**：两组主模型与Jev独立计费，使用2026-10-01核验的峰价快照，估算不是账单。累计已知峰价估算USD1停止追加，缺用量、需人工、服务异常或保护失败暂停；在途费用不受硬美元保证。未开始、已开始无结果、无判断的可证明零、未知费用分开。最终报告包含全部计划及失败，字/行删减与token/总体时间/任务收益分别表达，不把原生spill或恢复读回额外开销省掉。

## MODIFIED Requirements

无产品行为修改。增加本地受控实验材料与分析，复用已合并维护者管线和原生DSH接口；按2026-10-02追加授权归档公开案例摘要和结构化回执，并完成本地文档commit。

## REMOVED Requirements

无，不替换旧glob或DeepSWE结果，不删除已实施文档。

## 保持不变的行为

Jev默认功能关闭、原生Session/工具状态/spill/pruner/compaction继续由DSH拥有；日志失败保留原文，完整证据需求旁路。主模型做任务，不用人工回答或自动批准；新的产品修复、发布和扩大实验规模需对应方向。

## 输入、默认值、顺序与优先级

数据和真值仅人工构造，真实模型看到任务、emitter输出与必要恢复引用，不看到主代理评价标注。固定每例先baseline后开启、每条件一次，记录缓存与顺序限制。显式完整证据请求与工具不支持/错误优先旁路；被识别的test只走test-log分支，不再由general双重判断。当前12项开关均显式记录，除两日志开关及运行身份外相同。凭据只通过正常DSH机制或受保护stdin临时供给。

## 失败与回退

配置/原生接口缺失在收费前拒绝；实际模型调用后任何失败留证据，不自动重试。Jev低置信keep/unknown或净省不足不构成实验基础设施失败；超时/服务失败区分产品原文回退与本轮暂停追加。完整原文恢复缺失、保护信息丢失或用量缺失不补成功或零。

## 端到端传递

固定任务经支持DSH profile进入root Agent，原生bash执行emitter；现有post-execute形成候选/规则和Jev请求，采纳满足净省时保存原文并交付替换content，随后Host处理及Session记录最终结果。主模型按恢复引用read并报告指定日志事实，独立分析与原文真值核对；不改结构化value与exit语义。

## 对外契约

原日志/Session/账本在工作区被忽略的实验目录本地保留。2026-10-02追加授权要求将实际案例整理为仓库公开文档、按字段白名单导出的结构化结果及回执，并完成本地commit。保留六对结果、判断与实际采用、规则贡献、保护/恢复、版本哈希、费用与外推限制，补入口链接及实际管线说明；不复制原始Session、凭据、宿主路径或把一次性辅助脚本描述成已维护公开runner。验证导出数值、引用及敏感字段，显式暂存相关路径。未授权新的推送、合并或网站发布；不新增公共API、Node应用启动方式或通用评测SDK。原实验不同版本不混并，元数据不能替代真实原文/Session/ledger。

## 决策闭合

已确认：用户要求继续现有日志省略实验，真实DeepSeek/Jev接入和默认Docker内DSH完全权限授权沿用；本轮固定6例12试次和USD1追加控制是主代理选择，不是假称用户硬预算批准。代码事实：当前main7e208e0、12功能、两个日志分支及默认值来自output-admission/rules源码；原生bash非零退出与isError分离，待本轮mock实载核对。官方价格已核验且冻结，浮动DeepSeek模型别名仍记录限制。未决问题：无需用户决定的范围选择；源规则或原生预检若显示覆盖不成立，首次收费前修正人工输入并更新本Delta；需要产品语义修改则交主代理对齐。
