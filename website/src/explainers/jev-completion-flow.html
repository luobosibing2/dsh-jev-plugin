A

直接答案

普通完成核查的主流程

功能启用时，普通根 Agent turn 才使用这条流程。 本 turn 用过 Todo 即可核查，不要求条目全部 completed。 前一 turn 的 Todo 不自动触发本 turn 核查。 后来清空清单也不会抹去本 turn 的 Todo 使用记录。 Todo 更新本身不触发 Jev；简单任务无需创建 Todo。

这是报告完整性与一致性核查，不是对产物的独立验收。 如果 Todo 与最终回答一致地错报事实，Jev 未必能识别。 核查在回答已展示后运行，保留原始回答与后续补充。

B

主模型怎样提供依据？

沿用 content 与 status

插件通过 systemPrompt.section 提供简短提示。 仅在功能启用时提供，无需用户手工修改提示词。 不新增 Todo 字段，不要求事件编号或额外证据报告。

更新已有 Todo 时说明真实结果

简述实际动作、产物路径或已执行命令及观察结果。 失败、未验证和未完成部分如实保留，不编造依据。 不增加用户未要求的验证，不强制把所有检查改成通过。 无需为了完成核查而给简单任务创建 Todo。

虚构示例，不是一次实际执行记录：

{
  "content": "修复导出功能；src/export.ts；pnpm test export，12 项通过",
  "status": "completed"
}

测试是否必须通过，由用户要求决定。 “运行并报告测试”允许如实报告失败。 “修复并通过指定测试”在测试仍失败时尚未完成。

C

Jev 回答什么？

一次请求 · 两个 Choice

两个问题共享同一份输入，不是两次串行调用。

问题 输出 含义
assessment complete 报告显示要求已满足，未见明显遗漏或矛盾
assessment omission 要求未交代、明确未完成或规定条件未满足
assessment contradiction Todo 状态、完成说明或最终回答相互矛盾
assessment needs-user 完成依赖未解决的用户选择或授权
assessment unknown 所给材料不足，无法可靠判断
focus 已有要求、Todo 条目或最终回答 定位本次最关键问题
focus none 或整体材料 complete 可用 none；整体不足可选整体材料

插件生成位置编号，再将所选编号映射回原文。 没有进入 Todo 的要求，也能通过用户消息定位。 提示由结论类别、原文引用和固定模板组成。 每次只指出最关键的一处，不宣称列出全部问题。

不要求 Jev 自由生成长理由，不增加第三个生成问题。 概率或 confidence 可留作诊断，不显示为任务正确率。 缺少答案、格式错误或不存在的引用，按响应错误处理。 有效 unknown 是业务结论，不属于技术错误重试。

E

怎样补充与复核？

默认最多补充 3 次
结论或情况 后续行为
complete 记录报告核查结果，正常结束
omission，尚有额度 提示遗漏，主模型在原授权内补做
contradiction，尚有额度 引用矛盾位置，主模型核对并更正
unknown，尚有额度 提示材料不足，主模型补充真实依据或说明
needs-user 交用户决定，不自动继续
补充后再次停止 用完整最新材料重新核查
额度耗尽仍有问题 展示最后结论，停止自动补充

omission、contradiction 和 unknown 共用补充额度。 初次核查不占额度，默认最多 3 次补充、4 次正常核查。 设置上限为 N 时，正常核查最多 N+1 次。 结论类别改变不重置计数，剩余额度也不必用完。 技术重试不计入正常核查次数，不消耗或重置补充额度。

补充通过 agent.steer 进入同一 turn，Todo 不因此清空。 主模型更新相关条目，不自动重做其他已完成项。 缺失材料如实说明，不编造结果，不强制 completed。 补充不增加验收条件，也不授予新的修改权限。

设置页的“最多自动补充轮数”按 profile 保存。 默认 3，接受正安全整数；非法输入保留有效配置。 保存参数不会启用功能，也不改变 Goal 的无进展计数。

新 turn 只说“继续”时，不自动导入上轮要求。 无法取得完整原始要求时，提示材料缺失并等待用户处理。 摘要或上一轮回答不能替代缺失原文。 插件自己的补充消息不是新用户要求或授权。

evidenceChars 默认 24,000 字符，上限 1,000,000。 预算包含实际判断材料及必要规则和引用。 字符预算不保证判断提供方的 token 容量。
